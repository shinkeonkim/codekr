### M6 — 사람이 사람에게 말할 자리

여기까지는 **혼자 문제를 푸는 사이트**였다. 사용자가 만드는 것은 제출뿐이었고,
제출은 서로에게 말을 걸지 않는다. 커뮤니티가 붙으면 성격이 달라진다 —
**남이 쓴 것을 화면에 그리기 시작하고**(XSS), **사람이 나가도 남는 것**이 생긴다(탈퇴).

### M10 — 손으로 만든 UI 층을 shadcn 위로 옮긴다

`Select` 하나에서 시작했는데 **컴포넌트 층 전체의 문제**로 드러났다. 드롭다운을 열면
#206 의 테마 선택이 무시되고, 툴팁은 어떤 곳은 브라우저 기본 `title=` 이고 어떤 곳은
손으로 만든 것이다. 하나씩 만들어 메우는 대신 **shadcn/ui 를 들이기로 정했다.**

부딪히는 지점이 셋이다 — **다크 모드 방식**(`light-dark()` 한 벌 vs `.dark` 두 벌),
**토큰 이름**(`ink`/`surface` vs `foreground`/`background`), 그리고
**지금까지 UI 라이브러리가 없었다**는 것.

### M11 — 프로필이 사람의 자리가 된다

여기까지 프로필은 **서버가 계산한 숫자판**이었다. 푼 문제 수, 티어, 스트릭, 뱃지.
#83 이 그렇게 정했다 — "이미 공개된 것만 모은다".

그 뒤로 게시판(#137)·댓글(#138)이 붙어 **사람이 사람에게 말을 거는 사이트**가 됐다.
이제 프로필을 여는 이유가 "몇 문제 풀었나" 만이 아닌데, **그 사람이 쓴 것은 한 글자도
없고**, 이름은 못 바꾸며, 휴대폰에서는 자기 프로필에 갈 길조차 없다.

| # | 이슈 | 왜 지금인가 |
|---|---|---|
| [#309](https://github.com/shinkeonkim/codekr/issues/309) | 좁은 화면에 프로필 링크가 없다 | 데스크톱에서는 `UserLink`, 모바일에서는 **그냥 글자다.** #289 가 옮기며 링크를 잃었다 |
| [#310](https://github.com/shinkeonkim/codekr/issues/310) | 프로필 소개 문구 | 프로필이 **처음으로 사용자 입력을 싣는다.** 로그인 없이 열리는 화면이라 범위가 다르다 |
| [#307](https://github.com/shinkeonkim/codekr/issues/307) | `display_name` 과 `handle` 로 나눈다 | 오타로 가입하면 **계정을 지우는 것 말고 방법이 없다.** 푼 문제가 함께 사라진다 |

**보이는 이름(`display_name`)은 바꿀 수 있게, 주소가 되는 아이디(`handle`)는 못 바꾸게**
나눈다. **둘 다 유일하다.** 그러면 이름을 바꿔도 공유된 링크와 색인된 주소(#278)가 산다.
#204 가 문제 주소에서 한 판단(가리키는 것과 부르는 것을 나눈다)과 같은 결이다.

**순서:** #309 → #310 → #307. 앞의 둘은 작고 서로 닿지 않는다. #307 은 **한 PR 이
아니다** — 스키마·백필 → 주소 전환 → 변경 기능의 세 단계다.
그리고 **#285(데이터 초기화)와 함께 하면 가장 성가신 부분이 사라진다**:
기존 사용자의 `handle` 을 무엇으로 만들 것인가가 통째로 없어진다.

`next` 가 없으면 첫 화면으로 보낸다 (정해졌다).

에만** 넘긴다. 그때는 첫 칸이 제목이었으니 맞았는데, #204 가 번호를 앞에 넣으면서
**열 순서를 바꿨을 뿐인데 링크가 따라 옮겨 갔다.** `Column.href`(#197)가 이미 열마다
목적지를 선언하는 길이고 `rowHref` 는 쓰는 곳이 하나뿐이다 — **그 규칙을 없애는 쪽**을
본다. **#288 이 제출 번호를 맨 왼쪽으로 옮기고 있어 같은 함정에 들어갈 수 있다.**

**#313 의 순서는 정해졌다: #285(초기화) → #280(사칙연산 1~4번) → #313(5~9번).**
번호가 무엇이 되는지보다 **처음 온 사람이 만나는 순서**가 기준이다.
그리고 이것은 문제를 넣는 일이자 **SQL 채점 경로를 처음 돌리는 일**이다 —
#251 이 남긴 교훈과 같은 자리다. 만들어 두고 안 써 본 것은 안 되는 것과 구분되지 않는다.

### M13 — 계정을 잃지 않게

로그인 수단이 이메일과 비밀번호 하나뿐인데 **둘 중 하나를 잊으면 끝이다.**
메일을 보낼 방법 자체가 없어서(#233) 되찾을 길이 없다.

| # | 이슈 | 왜 지금인가 |

| [#233](https://github.com/shinkeonkim/codekr/issues/233) | 이메일 인증 | 발송 경로가 없다. **아래 전부의 선행이다** (PR #344) |
| [#355](https://github.com/shinkeonkim/codekr/issues/355) | 메일 발송을 운영에 붙인다 | #344 는 **로컬까지다.** 차트에 설정이 없고, Daum 은 465/SSL 인데 코드는 STARTTLS 뿐이다 |

**순서는 뒤집을 수 없다.** #233 이 발송 경로를 주기도 하지만, 더 중요한 것은
**인증되지 않은 주소로 재설정을 보내면 안 된다**는 것이다 — 아무 주소나 적고 가입할 수
있는 지금 상태에서 재설정을 붙이면 **남의 주소로 가입한 계정을 그 주소 주인이
가져간다.** 순서가 뒤바뀌면 이 기능이 계정 탈취 경로가 된다.

**#355 가 그 사이에 낀다.** #344 를 머지해도 차트에 `CODEKR_MAIL_*` 이 없어
`host` 가 비고, 그러면 설계대로 **"보낼 수 없으면 요구하지도 않는다"** 가 발동해
**인증 기능이 꺼진 채 배포된다.** 안전하게 도는 것이지 켜진 것이 아니다.
발송 계정은 `contact@shinkeonkim.com`(Daum 스마트워크)로 정해졌다 —
**인증 계정과 발신 주소가 같아야** SPF/DKIM 이 맞는다.

**그리고 이 저장소는 public 이다.** 앱 비밀번호가 한 번 들어가면 커밋을 지워도
되돌릴 수 없다. `values.yaml` 에는 **시크릿 이름만**, 값은 SOPS 에만 둔다 —
`postgres.secretName`·`storage.secretName` 이 이미 그 패턴이다.
`docs/09` §7 의 시크릿 표에 **어디에 두는지와 새 나갔을 때 무엇을 하는지**가 없다.

### M14 — CI 를 손으로도 돌릴 수 있게

| # | 이슈 | 왜 지금인가 |
|---|---|---|
| [#317](https://github.com/shinkeonkim/codekr/issues/317) | CI 수동 트리거와 옵션 | 커밋을 밀지 않으면 아무것도 안 돈다. **30분짜리 `sandbox-live` 만 따로 돌릴 방법이 없다** |
| [#343](https://github.com/shinkeonkim/codekr/issues/343) | 여러 대상 선택 + 이미지 빌드 옵션 | #317 이 **하나만 고르게** 뒀다. `workflow_dispatch` 에 **다중 선택 타입이 없다** |
| [#348](https://github.com/shinkeonkim/codekr/issues/348) | 배포 전용 워크플로 | **특정 버전을 다시 배포할 길이 없다.** #248 때 손으로 메울 방법이 없었다 |

`workflow_dispatch` 한 줄을 넣는 일이 아니다. 모든 잡이 `paths-filter` 의 결과
(`needs.changes.outputs.*`) 뒤에 있는데, **수동 실행에는 비교할 PR 이 없다.**
그 게이트를 입력과 어떻게 잇느냐가 실제 작업이다.

**조심할 것 셋:** main 에서 수동 실행하면 `images`·`release` 가 돌아
**손으로 CI 를 돌린 것이 배포가 된다.** `concurrency` 가 같은 ref 의 진행 중 CI 를
**취소한다.** 그리고 옵션을 다 끄면 **아무것도 안 돌고 초록이다** — #248 이 겪은 모양
그대로다.

**#317 은 그 셋을 가장 좁게 풀었다** — 대상을 하나만 고르게 하고, `images`·`release`
를 push 전용으로 아예 막고, `concurrency` 그룹에 이벤트 이름을 넣었다.

**넓히되 배포는 CI 에 넣지 않는다.** CI 는 "이 커밋이 쓸 만한가" 를 판정하는 곳이고,
**재배포에는 이미지 빌드가 필요 없다**(이미 ghcr 에 있다). 그래서 #343 은 다중 선택과
이미지 빌드만 맡고, **배포는 #348 이 전용 워크플로로 한다.** 경로가 둘이 되는 것은
같지만 **의도가 분명한 둘**이 된다 — 자동(머지)과 수동(재배포).

**#348 이 먼저 갈라야 할 것:** "재배포" 가 셋이다. (a) 다른 sha 로 바꾸기,
(b) CI 가 태그를 못 적은 경우(#248) — 이 둘은 워크플로가 푼다. 그런데
**(c) 같은 sha 를 그대로 다시**는 `values-release.yaml` 이 안 바뀌므로 커밋이 없고,
**ArgoCD 는 아무 일도 하지 않는다.** 조용히 성공하지 않게 하는 것이 중요하다.
그리고 CI 의 `release` 는 `needs: images` 로 이미지 존재를 보장받지만
**수동 배포에는 그 보호가 없다** — 오타 하나가 ImagePullBackOff 다.

### M15 — 배포가 남기는 것을 치운다

CD 가 붙고(#246) 나서 **배포가 자주 나가기 시작했다.** 그러면서 배포가 남기는 것도
같이 쌓이는데, 치우는 규칙을 아무 데도 적어 두지 않았다.

| # | 이슈 | 왜 지금인가 |
|---|---|---|
| [#320](https://github.com/shinkeonkim/codekr/issues/320) | 오래된 ReplicaSet 이 쌓인다 | `revisionHistoryLimit` 이 **어디에도 없다.** 기본 10 × 워크로드 6개 |

**앱 다섯이 `global.imageTag` 하나를 공유한다.** #246 이 머지마다 그 태그를 커밋 sha 로

열 번 머지하면 트리가 찬다.

그리고 **이 이력은 쓰이지 않는다.** §5.1 이 정한 되돌리기는 `kubectl rollout undo` 가
아니라 **git revert → 태그 되돌리기**다. 쓰지 않는 이력을 워크로드마다 열 개씩 들고 있다.

### M16 — 역할은 갖췄는데 그 역할이 쓸 화면이 없다

"문제도 내고 게시판도 보는 사람이 있다."

**문제는 거를 메뉴가 없다는 것이다.** 어드민 화면은 문제·큐·운영 작업 셋뿐이라,
`CONTEST_MANAGER` 나 `BOARD_MANAGER` 를 줘도 **빈 화면을 본다.**

(#336 이 만드는 것은 게시판 관리가 아니라 **글·댓글 관리**다).
문제 폼의 **등록과 수정은 모양이 달라도 되지만 겹치는 것은 한 벌**이다 —
구획 컴포넌트(#127 이 쪼갠 것)와 **검증·저장**은 반드시 공유한다.

적기만 하면 서울대가 된다 — M13 이 그것을 세운다.

**정해진 것 셋.** 소속은 **여럿**이다 — 확인한 메일마다 붙고 주 소속을 고르지 않는다.
**졸업·퇴사는 다루지 않는다** — 계정 회수 시점을 우리가 알 수 없고, 주기적 재확인은
쓰는 사람에게 계속 일을 시키는 것이다. 도메인 목록은 **요청을 받아** 어드민이 넣는다 —
요청 폼은 만들지 않는다. 요청이 실제로 오는 것을 보고 만든다.

**그룹끼리의 랭킹은 안 만든다.** 합이면 머릿수가 이기고, 평균이면 **잘하는 사람만
남기고 내보내는 유인**이 생긴다. 뒤엣것은 사람에게 나쁘게 작동한다.
소속끼리는 겨룬다 — 인원을 도메인이 정하므로 조작할 수 없다.

## 4. 브랜치 · PR 전략 (Stacked PR)

> 실제 작업 절차와 규칙은 [`docs/10_작업_방식.md`](10_작업_방식.md) 에 있다.
> 이 절은 개요만 남긴다.

작업이 밀려도 리뷰가 막히지 않도록 **스택 형태로 브랜치를 쌓고 PR 을 모두 열어둔다**.

```
main
 └─ feat/01-docs                 (PR → main)
     └─ feat/02-monorepo         (PR → feat/01-docs)
         └─ feat/03-api-core     (PR → feat/02-monorepo)
             └─ …
```

- 각 PR 은 이슈 하나에 대응하고 본문에 `Closes #N` 을 포함한다.
- 커밋 메시지 형식: `<type>(<scope>): <요약> (#<issue>)`
  - 예: `feat(api): JWT 인증 필터 및 로그인 API 추가 (#4)`
- 앞선 PR 이 머지되면 뒤따르는 PR 의 base 를 순서대로 옮긴다.
