# 함수만 구현하는 문제 — 하네스 기획

- 상태: 초안 (구현 전)
- 근거 이슈: #421
- 선행: **#419(문제별 허용 언어)** — "하네스를 쓴 언어로만" 이 그 위에 선다
- 관련: #42(문제 유형 확장 기획), #60(SQL 유형 — 유형을 하나 늘린 전례), #12(템플릿),
  #337(문제 폼 구획), #97(런타임별 제한), #107·#57(부분 점수를 열면 흔들리는 곳)

## 1. 왜 지금 정하는가

지금 낼 수 있는 문제는 **프로그램 하나를 통째로 쓰는 것**뿐이다. 그래서 사용자는
입력을 읽고 출력을 찍는 것을 매번 다시 쓴다 — **그것이 문제의 주제가 아닐 때도.**

그리고 이 일은 **실행기의 전제를 바꾼다.** 지금 실행기는 "소스 하나를 정해진 이름으로
쓰고 정해진 명령을 돈다". 파일이 둘이 되는 순간 런타임 정의·오류 메시지·샌드박스 검증이
함께 움직인다. 정하지 않고 손대면 **되돌리기 어려운 쪽부터 굳는다.**

## 2. 첫 번째 결론 — 쪼갠다. 다섯이다

#421 이 스스로 "한 PR 이 아니다" 라고 적었다. #60(SQL 유형)이 갔던 길을 그대로 쓴다.

| 순서 | 무엇 | 왜 이 순서인가 |
|---|---|---|
| 1 | **실행기가 파일 여럿을 받는다** | 가장 어렵고 나머지가 전부 여기 기댄다. 이것만으로도 값이 있다 — 여러 파일 실행은 하네스 말고도 쓸 데가 생긴다 |
| 2 | **문제에 언어별 하네스를 담는다** (스키마·도메인) | 실행기가 받을 수 있어야 저장할 뜻이 생긴다 |
| 3 | **채점기가 하네스를 실어 보낸다** + 누출 차단 | 여기까지가 "돌아간다" 의 끝이다 |
| 4 | **어드민이 하네스를 쓴다** | 사람이 넣을 수 있어야 문제가 생긴다 |
| 5 | **사용자 화면이 껍데기를 준다** | 마지막이다. 앞이 없으면 보여 줄 것이 없다 |

**1과 2를 붙이지 않는다.** 붙이면 실행기 변경이 문제 스키마에 묶여, 실행기만 되돌리고
싶을 때 함께 되돌려야 한다.

## 3. 합치는 방식 — 런타임 정의가 안다

세 갈래가 있었고 **런타임 정의**를 고른다.

| 방법 | 대가 |
|---|---|
| **런타임 정의에 파일 배치와 명령을 적는다** | `runtimes.yaml` 이 커진다. 대신 **한 곳에 모인다** |
| 하네스에 `{{USER_CODE}}` 자리를 만든다 | 단순하지만 **문자열을 이어 붙이는 것**이라 줄 번호가 통째로 어긋난다 |
| 언어마다 실행기 코드에 분기 | 언어가 늘 때마다 실행기를 고쳐야 한다 |

```yaml
- id: "python:3.13"
  sourceFile: "solution.py"          # 사용자 코드가 이 이름으로 저장된다
  harness:
    file: "main.py"                  # 하네스가 이 이름으로 놓인다
    run: ["python", "main.py"]       # 하네스를 돌린다 — 사용자 코드는 import 된다
```

**파일이 나뉘어 있어야 줄 번호가 산다.** 그것이 이 선택의 이유 전부다.

`harness` 가 없는 런타임은 **함수형 문제를 지원하지 않는다** — 그리고 그것이 곧
#419 의 허용 목록이 된다(4절).

## 4. 하네스를 쓴 언어로만 — #419 를 그대로 쓴다

**새 규칙을 만들지 않는다.** 문제에 하네스를 쓴 언어가 곧 허용 목록이다.

- 하네스가 없는 언어는 **문제 상세에 나오지 않고**, 서버가 제출을 막는다 (#419 가 이미
  그렇게 한다)
- 그래서 함수형 문제는 **"파이썬 문제"·"C++ 문제"** 가 된다. 출제자가 쓴 만큼만 열린다
- 허용 목록을 손으로 또 고르게 하지 않는다 — **두 곳이 같은 것을 정하면 어긋난다**

## 5. 새 `problemKind` 를 둔다

`JUDGE_FUNCTION` 이다. `JUDGE_STDIO` 에 얹지 않는다.

- 채점기·실행기가 **분기할 자리**가 이미 `problemKind` 다 (#59)
- 얹으면 "하네스가 있으면 함수형" 이라는 **암묵 규칙**이 생긴다. 하네스를 지웠을 때
  문제의 성격이 조용히 바뀐다
- 화면도 갈라야 한다 — 템플릿이 "시작 코드" 가 아니라 **"채워야 할 껍데기"** 다

## 6. 줄 번호 — 거르지 않고 **되돌린다**

**거르는 쪽을 고르지 않는다.** 하네스 줄을 지워 버리면 진짜 원인이 감춰진다.

```
파일을 나눈다 → 컴파일러가 파일 이름을 함께 찍는다 → 사용자 파일의 줄 번호는 그대로다
```

그 위에 두 가지를 더 한다.

1. **경로를 지운다.** `/work/solution.py:12` → `solution.py:12`. 컨테이너 안의 경로는
   사용자에게 뜻이 없고, 그 자체가 내부 구조다
2. **하네스에서 난 오류는 사실만 남긴다.** `main.py:41: NameError: solve` 처럼 하네스
   파일에서 난 것은 **"하네스에서 났다"** 로 바꾼다 — 하네스의 코드는 보이지 않되,
   **오류가 났다는 사실과 그 종류는 보인다.** 그것을 감추면 "왜 안 되는지 모르는 상태"
   가 되고, 그것은 이 기능을 쓸 수 없게 만든다

**언어별로 다르게 어긋나는 것은 그때 본다.** 지금 정할 수 있는 것은 규칙이고, 각 언어의
실제 출력은 하네스를 붙여 보면서 확인한다 — 그 확인이 1단계의 완료 조건이다.

## 7. 하네스가 새면 안 된다 — 네 갈래를 다 막는다

**샌드박스가 막아 주지 않는다.** 사용자 코드와 하네스는 같은 프로세스에서 돈다.

| 새는 길 | 막는 법 |
|---|---|
| 표준 출력·오류 | 6절의 규칙. 하네스 파일에서 난 것은 내용 대신 사실만 |
| **사용자 코드가 파일을 읽는다** | 하네스 파일을 **실행 직전에 지운다**(인터프리터가 이미 읽은 뒤) 또는 컨테이너가 읽을 수 없는 자리에 둔다. **언어마다 되는 방법이 다르다** — 1단계에서 언어별로 확인한다 |
| 스택 트레이스 | 6절과 같은 규칙으로 지운다 |
| **컴파일된 산출물** | C++·자바처럼 컴파일하는 언어는 **산출물에 하네스 소스가 남지 않는지** 확인한다 (디버그 심볼) |

**이것을 검증으로 남긴다.** #246 이 실행기 자체 검사(`selftest`)를 만들어 두었으므로
그 자리에 "하네스가 새지 않는다" 를 더한다 — 사람이 눈으로 보는 확인은 배포 때마다
사라진다.

## 8. 열지 않는 것

- **부분 점수를 열지 않는다.** 함수 단위 호출이면 가능해지지만, 판정 모델(#107)과
  점수(#57)가 "맞았다/틀렸다" 를 전제로 서 있다. 열면 랭킹까지 흔들린다 —
  **그것은 별도의 기획이 필요한 크기다**
- **기존 문제를 옮기지 않는다.** 두 방식이 공존한다. stdio 문제는 그대로 돈다
- **여러 번 호출하는 문제(자료구조 설계)를 1차에서 다루지 않는다.** 하네스가 그것을
  할 수 있게는 되지만, 입력 형식을 정하는 일이 따로 크다

## 8.1 어디까지 섰나 (#421 구현됨)

| 순서 | 무엇 | 상태 |
|---|---|---|
| 1 | 실행기가 파일 여럿을 받는다 | **섰다** (#457) |
| 2 | 문제에 언어별 하네스를 담는다 | **섰다** — `problem_harnesses` |
| 3 | 채점기가 하네스를 실어 보낸다 | **섰다** — 작업에 제출한 언어의 것이 실린다 |
| 4 | 어드민이 하네스를 쓴다 | **API 로 된다.** 폼 구획(#337)은 남았다 |
| 5 | 사용자 화면이 껍데기를 준다 | **섰다** — 껍데기가 시작 코드로 내려간다 |

**줄 번호가 사용자 코드 기준으로 나오는 것**을 라이브 시험이 확인한다 — 하네스를 이어
붙였다면 세 줄짜리 코드에서 "5번째 줄" 오류를 보게 된다.

## 10. 이 문서가 답하지 않은 것

- **어느 언어부터 하네스를 지원할 것인가.** 파이썬이 가장 쉽고(import 하나) C++·자바가
  어렵다. 1단계에서 파이썬 하나로 끝까지 가 보고 정하는 편이 낫다
- **하네스를 문제 사이에 재사용할 것인가.** 비슷한 문제 열 개가 같은 하네스를 쓰는 일이
  생길 텐데, 그때 복사해 두면 고칠 때 열 곳을 고친다. **재사용은 실제로 그 일이 생긴
  뒤에 본다** — 지금 만들면 쓰지 않는 추상이 된다
- **하네스의 실행 시간을 누구 몫으로 볼 것인가.** 제한(#97)은 프로그램 전체에 걸린다.
  하네스가 무거우면 사용자 코드가 억울해진다 — 하네스를 가볍게 쓰는 것으로 시작하되,
  실제로 문제가 되면 그때 나눈다
