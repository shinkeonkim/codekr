# AI 출제 보조 — 제공자를 바꿔 끼울 수 있게

- 상태: 초안
- 근거: #230(이미 들어간 초안 도구), #480·#481·#482(로컬 스킬), #479·#537(묶음 형식)

## 1. 먼저 — **이미 절반은 되어 있다**

"AI 로 출제를 돕는다" 는 **이 저장소에 이미 있다.** #230 이 그것이고 PR #387 로
들어갔다. 새로 만드는 이야기가 아니라 **어디까지 되어 있고 무엇이 비었는지**부터
확인하고 시작한다 (#82 의 선례 — 되어 있는 것을 다시 만들 뻔했다).

| 있는 것 | 어디 |
|---|---|
| 지문 → 폼 초안 (제목·입출력 설명·예제·유형·난이도·제한) | `problem/draft/ProblemDraftService.kt` |
| **OpenAI 호환 엔드포인트를 주소로 받는다** | `ProblemDraftProperties.baseUrl` |
| 키가 없으면 기능이 **없다** (404) | `enabled = apiKey.isNotBlank()` |
| 프롬프트 주입 방어 (지문을 구분선으로 감싼다) | `STATEMENT_FENCE` |
| 모델 출력을 **믿지 않고** 자른다 | `DraftParser` |
| 사람당 분당 호출 제한 | `perMinuteLimit = 10` |
| 관리 기록에 남는다 (#225) | `AdminProblemDraftController` |
| 어드민 화면 | `features/problem-editor/ui/DraftFromStatement.tsx` |

### LiteLLM 은 **코드를 고치지 않고 붙는다**

`ProblemDraftProperties.baseUrl` 이 이미 환경 변수다.

```
CODEKR_DRAFT_BASE_URL: ${CODEKR_DRAFT_BASE_URL:-https://api.openai.com/v1}
```

LiteLLM 프록시는 **OpenAI 호환 `/v1/chat/completions`** 를 연다. 그러므로

```
CODEKR_DRAFT_BASE_URL=http://litellm:4000/v1
CODEKR_DRAFT_API_KEY=sk-codekr-...      # 프록시의 가상 키
CODEKR_DRAFT_MODEL=문제-초안             # 프록시가 정한 별명
```

이 셋만 바꾸면 **api 코드는 한 줄도 안 바뀐다.** 그래서 이 기획의 일은
"라이브러리를 고르는 일" 이 아니라 **"프록시를 어디에 두고 키를 어떻게 다루는가"** 다.

## 2. 왜 라이브러리가 아니라 프록시인가

**LiteLLM 은 파이썬이다.** api 는 Kotlin/JVM 이라 그 라이브러리를 넣을 방법이 없다.
선택지는 셋이었다.

| 방법 | 문제 |
|---|---|
| JVM 쪽 LLM 추상 라이브러리 (LangChain4j 등) | 의존성이 크고, **제공자가 늘 때마다 api 를 재배포**한다 |
| 제공자별 코드를 우리가 쓴다 | 지금 그 상태다. 제공자 하나까지는 괜찮고 둘부터 아니다 |
| **LiteLLM 프록시** | 프로세스가 하나 는다 |

프로세스가 하나 느는 대신 얻는 것이 셋이다.

1. **제공자 교체가 배포가 아니다.** 프록시 설정 파일 한 줄이다
2. **제공자 키가 api 에서 사라진다.** api 는 프록시의 가상 키만 든다 —
   새어도 **그 키만 돌리면** 되고, 제공자 계정 전체가 열리지 않는다
3. **폴백과 예산이 공짜로 온다.** OpenAI 가 죽으면 다른 제공자로 넘어가고,
   월 한도를 넘으면 프록시가 막는다. 우리 코드에 그것을 쓰지 않아도 된다

> **덤 하나.** 지금은 **api 파드가 인터넷으로 나가야** 한다. 프록시를 두면 나가는 것은
> 프록시뿐이고, **api 의 egress 를 좁힐 수 있다** — 실행기에 이미 그런 정책이 있다(#47).
> 이것은 이 변경이 보안을 *늘리는* 쪽이라는 뜻이다. 지금은 반대로 읽기 쉽다.

## 3. 정할 것

### 3.1 프록시를 어디에 두는가

| | 로컬 | 운영 |
|---|---|---|
| 어디 | `infra/docker/compose.yml` 에 서비스 하나 | 차트에 Deployment + Service |
| 이미지 | `ghcr.io/berriai/litellm:main-stable` | 같은 것을 태그 고정해서 |
| 설정 | `infra/litellm/config.yaml` (저장소에) | ConfigMap 으로 같은 파일 |
| 키 | `.env` (개인 것, `.gitignore`) | **SOPS 시크릿** (#355 와 같은 규칙) |

**끄고도 스택이 떠야 한다.** 지금 규칙이 그렇다 — 키가 없으면 기능이 없고 서비스는
돈다. 프록시가 없어도 같아야 한다. compose 의 `profiles:` 로 **기본은 안 뜨게** 둔다.

### 3.2 DB 를 붙일 것인가

LiteLLM 은 **설정 파일만으로도 돈다**(마스터 키 하나). Postgres 를 붙이면 가상 키를
여럿 만들고 **키마다 예산·사용량**을 볼 수 있다.

**처음에는 붙이지 않는다.** 쓰는 곳이 하나(어드민 초안)이고, DB 를 붙이는 순간
백업(#281)·마이그레이션·복원 대상이 하나 늘어난다. **키가 둘 이상 필요해질 때** 붙인다.

### 3.3 무엇을 별명으로 열 것인가

**모델 이름을 그대로 쓰지 않는다.** `gpt-4o-mini` 를 `CODEKR_DRAFT_MODEL` 에 적으면
모델을 바꿀 때 그 값을 고쳐 **api 를 재배포**해야 한다. 프록시에 **일 이름**을 연다.

```yaml
model_list:
  - model_name: 문제-초안              # ← api 가 부르는 이름
    litellm_params: { model: openai/gpt-4o-mini }
  - model_name: 문제-초안              # 같은 이름을 여럿 두면 라우팅·폴백이 된다
    litellm_params: { model: anthropic/claude-haiku-4-5 }
```

일이 늘면 이름이 는다(`정답-코드`, `반례-데이터`). **모델이 아니라 일이 단위다.**

### 3.4 예산

**월 한도를 프록시에 건다.** 어드민만 쓰는 기능이라 남용 위험은 낮지만, 위험한 것은
남용이 아니라 **고장난 반복 호출**이다. api 쪽 분당 제한(#230)은 사람 단위라
파드가 여럿이면 그만큼 곱해진다 — **돈을 지키는 층은 프록시여야 한다.**

## 4. 지금 비어 있는 것

### 4.1 **운영에서는 이 기능이 꺼져 있다**

`deploy/charts/codekr/templates/config.yaml` 에 `CODEKR_DRAFT_*` 가 **한 줄도 없다.**
`CODEKR_MAIL_*` 는 있다. 그래서 배포된 코드에서 초안 만들기는 `apiKey` 가 비어
**404 로 답한다** — 안전하게 도는 것이지 켜진 것이 아니다.

**#355 와 완전히 같은 모양이다.** 그때도 코드는 들어갔는데 차트에 값이 없어
"설계대로 꺼진 채" 배포됐다.

### 4.2 AI 가 닿는 곳이 **한 군데뿐이다**

출제는 네 단계인데 도구가 붙은 곳은 첫 칸뿐이다.

```
지문 정리  →  테스트케이스  →  정답 코드  →  검수(반례)
   ↑            ↑                ↑            ↑
 #230 (제품)   #482 (로컬 스킬)  #481 (로컬)  #482 (로컬)
```

#480·#481·#482 는 **Claude Code 스킬**이다 — 저장소를 클론하고 Claude Code 를 쓰는
사람만 쓸 수 있다. 어드민 화면에서 문제를 만드는 사람은 못 쓴다.

**전부 제품으로 옮기자는 것이 아니다.** 스킬이 나은 이유가 있다 — 대화가 길고,
산출물이 커밋되면 안 되고(#480), 사람이 붙어 다듬어야 한다. **어느 것을 옮길지가
판단이고, 그 판단은 프록시가 선 뒤에 한다.** 옮길 후보는 "짧게 한 번 묻고 끝나는 것"
이다: 지문에서 **빠진 것 찾기**, 등록 직전 **경계값 점검**.

## 5. 하지 않기로 한 것

- **AI 가 문제를 저장하지 않는다.** #230 이 정한 것을 그대로 지킨다 — 마지막은 사람이고,
  마지막 방어선은 정답 코드 검증(#39)이다
- **사용자 쪽에 AI 를 열지 않는다.** 힌트·풀이 설명은 다른 문제다 —
  **틀린 힌트가 학습을 망가뜨리는 것**은 틀린 초안이 사람 검토에 걸리는 것과 급이 다르다
- **스킬 셋(#480·#481·#482)을 제품으로 옮기지 않는다** (지금은). 4.2 참조

## 6. 순서

1. **차트에 `CODEKR_DRAFT_*` 를 넣는다** — 지금 있는 기능을 켜는 일이다. 가장 작고 가장 급하다
2. **LiteLLM 프록시를 로컬에 세운다** — compose 프로필 + 설정 파일. 여기서 별명·폴백을 정한다
3. **운영에 올린다** — 차트, 시크릿, api egress 좁히기
4. **AI 가 닿는 곳을 넓힐지 정한다** — 2·3 이 서고 나서

**1 은 2 를 기다리지 않는다.** 프록시가 없어도 `CODEKR_DRAFT_BASE_URL` 이 OpenAI 를
그대로 가리키면 된다 — 그것이 지금의 기본값이다.
