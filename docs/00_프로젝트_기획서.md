# 00. 프로젝트 기획서 — 코드.kr

## 1. 배경

기존 코드.kr 은 별개의 컨텐츠를 담고 있었다. 이번 프로젝트는 그 도메인 위에서
**새로 시작하는 오픈소스 코딩 테스트 플랫폼**이다. 기존 컨텐츠와의 호환이나
마이그레이션은 고려하지 않는다.

## 2. 문제 정의

코딩 테스트 준비 도구는 많지만, 다음 세 가지를 동시에 만족하는 것은 드물다.

1. 알고리즘 외에도 **SQL · 네트워크 · OS · 시스템 설계 등 폭넓은 유형**을 다룬다.
2. 채점이 블랙박스가 아니라 **실행 과정을 실시간으로 보여준다**.
3. 문제 등록/운영이 **플랫폼 안의 관리 화면**으로 끝난다.

코드.kr 은 이 셋을 목표로 한다.

## 3. 목표 (MVP)

| # | 목표 | 성공 기준 |
|---|---|---|
| G1 | 이메일/비밀번호 인증 | 가입 → 로그인 → JWT 로 보호 API 접근 |
| G2 | 문제 탐색 | 카테고리·난이도 티어·키워드 필터가 있는 목록과 상세 화면 |
| G3 | 코드 실행 | 에디터에서 임의 입력으로 코드를 실행하고 stdout/stderr 확인 |
| G4 | 코드 채점 | 제출 시 테스트케이스 전체를 채점하고 판정 반환 |
| G5 | 실시간 채점 뷰 | 테스트케이스 단위 진행 상황이 WebSocket 으로 즉시 표시 |
| G6 | 어드민 문제 관리 | 어드민이 문제/테스트케이스/언어별 초기 코드를 등록·수정·삭제 |
| G7 | 로컬 재현성 | `make up && make seed` 로 전체 스택이 로컬에서 동작 |

## 4. 비범위 (MVP 에서 하지 않는 것)

- 소셜 로그인, 이메일 인증 메일 발송, 비밀번호 재설정
- 사용자 랭킹·뱃지, 커뮤니티(질문/풀이 공유)
  (문제 난이도 티어는 MVP 범위 안이다 — 사용자 등급과는 다른 개념)
- 대회(Contest) 모드, 표절 검사
- SQL/시스템 설계 유형의 **전용 채점기** — 스키마상 유형은 표현하되, MVP 채점은
  stdin/stdout 기반 유형만 지원한다
- k8s 실제 배포 (설계는 하되 M2 에서 수행)

이 항목들은 [ADR-0006](adr/0006-mvp-범위-축소.md)에 근거와 함께 남긴다.

## 5. 사용자와 시나리오

### 5.1 학습자 (ROLE_USER)

1. 가입/로그인한다.
2. 문제 목록에서 카테고리(알고리즘/SQL/네트워크…)와 난이도 티어(브론즈~루비)로 좁힌다.
3. 문제 상세에서 지문을 읽고, 오른쪽 에디터에서 언어와 버전을 고른다.
4. **실행**으로 직접 입력한 stdin 에 대해 결과를 확인한다.
5. **제출**하면 테스트케이스가 1번부터 순서대로 채점되는 과정이 실시간으로 흐른다.
6. 최종 판정(정답/오답/시간 초과/메모리 초과/런타임 에러/컴파일 에러)을 본다.

### 5.2 운영자 (ROLE_ADMIN)

1. `/admin/problems` 에서 문제를 등록한다 — 지문, 난이도 티어, 제한(시간/메모리),
   테스트케이스, 언어별 초기 코드.
2. 테스트케이스는 **공개(예제)** 와 **히든** 으로 나뉜다. 히든은 API 응답에 절대 포함되지 않는다.
   문제마다 언어/버전별 초기 코드를 지정할 수 있고, 지정하지 않은 언어는 기본 템플릿을 쓴다.
3. 잘못 만든 문제는 삭제할 수 있다. 삭제는 소프트 삭제라 **제출 이력은 그대로 남는다** (ADR-0007).
4. `/admin/queues` 에서 채점/실행 큐의 적체 상황을 확인한다.

## 6. 제품 범위 — 화면 목록

| 경로 | 설명 | 권한 |
|---|---|---|
| `/` | 랜딩 | 공개 |
| `/signup`, `/login` | 가입/로그인 | 공개 |
| `/problems` | 문제 목록(검색/필터/페이징) | 공개 |
| `/problems/[slug]` | 문제 상세 + 에디터 + 실시간 채점 | 공개(제출은 로그인) |
| `/submissions/[id]` | 제출 결과 상세 | 본인/어드민 |
| `/submissions` | 내 제출 목록 | 로그인 |
| `/admin/problems` | 문제 관리 목록 | 어드민 |
| `/admin/problems/new`, `/admin/problems/[id]/edit` | 문제 등록/수정 | 어드민 |
| `/admin/queues` | 큐 모니터링 | 어드민 |

## 7. 기술 스택

요구사항에서 지정된 스택을 그대로 사용한다.

- **프론트엔드**: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS, Bun
- **백엔드**: Kotlin, Spring Boot 4, Spring Security, Spring Data JPA, Querydsl,
  Spring WebSocket, Spring Boot Actuator
- **실행/채점**: Go (실행기, 채점기), OCI 런타임 샌드박스
- **데이터**: PostgreSQL 16, Redis 7 (Streams = 큐, Pub/Sub = 실시간 이벤트, 캐시)
- **인프라**: Docker (로컬), Kubernetes + ArgoCD GitOps (M2)

각 선택의 근거는 [`docs/adr/`](adr/) 에 있다.

## 8. 품질 기준

- 코드 파일은 200 라인을 넘지 않게 분리한다. 함수는 하나의 책임만 진다.
- 도메인 로직은 프레임워크 의존 없이 테스트 가능해야 한다.
- 모든 외부 입력(요청 바디, 쿼리 파라미터, 제출 코드)은 경계에서 검증한다.
- 비밀번호는 BCrypt, 토큰 서명 키·DB 자격증명은 환경 변수로만 주입한다.
- 무거운 통합 테스트(Testcontainers, 샌드박스 실행)는 CI 에서 별도 잡으로 분리한다.

## 9. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 샌드박스 탈출 / 자원 고갈 | 치명적 | 네트워크 차단, 읽기 전용 rootfs, non-root, cgroup 메모리·CPU·pids 제한, 실행 노드 격리 |
| 채점 큐 적체 | 사용자 체감 지연 | Consumer group 으로 워커 수평 확장, 큐 모니터링 API/화면 |
| 실행기 장애로 제출이 영원히 대기 | 사용자 이탈 | 채점기에 작업 타임아웃 + 재시도, 최종 실패는 `SYSTEM_ERROR` 로 종결 |
| 언어/버전 추가 비용 | 확장성 저하 | 실행 런타임을 **설정 데이터**로 정의 (코드 변경 없이 추가) |
| Java/Kotlin 컴파일 지연 | 채점 지연 | MVP 지원 언어를 Python/JS/C++ 로 한정, 워밍업은 M2 |
