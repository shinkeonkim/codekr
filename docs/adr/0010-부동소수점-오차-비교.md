# ADR-0010. 부동소수점 허용 오차 비교를 도입한다

- 상태: 채택
- 날짜: 2026-08-13
- ADR-0006 의 "부동소수점 허용 오차 비교, 스페셜 저지 — 필요할 때" 를 **대체한다**

## 배경

ADR-0006 은 MVP 범위를 줄이며 오차 비교를 미뤘다. 근거는 "필요한 문제가 아직 없다" 였다.

**필요해졌다.** `A / B` 를 낼 수 없다 — 지금 채점은 문자열 완전 일치라 `7 / 2` 의 답을

- `3.5` 로 낸 제출과
- `3.500000` 으로 낸 제출과
- `3.4999999999999996` 으로 낸 제출이

전부 다른 답이 된다. 셋 다 맞은 답인데 갈린다. 그리고 그 차이는 **푸는 사람의 실력이
아니라 언어의 기본 출력 자릿수**에서 온다.

## 결정

문제마다 **출력 비교 방식**을 정한다.

| 방식 | 무엇 |
|---|---|
| `EXACT` (기본) | 지금까지의 동작. 줄 끝 공백과 끝의 빈 줄만 무시하고 정확히 맞춘다 |
| `FLOAT` | 토큰마다 숫자로 읽히면 오차 안에서 비교한다 |

### 문제 단위다

케이스 단위가 아니다. 한 문제 안에서 케이스마다 정밀도가 다른 경우는 드물고, 케이스마다
두면 어드민이 채워야 할 칸이 케이스 수만큼 늘어난다. 계약에도 `JudgeJob` 에 한 번만 싣는다.

### 절대·상대 오차 중 하나만 만족하면 맞다

답이 `0.0000001` 일 때와 `1000000.5` 일 때 같은 절대 오차를 쓸 수 없다. 지금 필요한
문제(#280 — 정답이 −128~127)에는 절대 오차만으로 충분하지만, **나중에 쓸 수 없는 것을
지금 만들 이유가 없다.**

### 토큰 단위로 비교한다

출력이 실수 하나가 아닐 수 있고 숫자와 글자가 섞인 줄도 있다("Case 1: 3.5"). 공백으로
쪼개고 토큰마다 숫자로 읽히면 숫자로, 아니면 글자로 비교한다. **토큰 개수가 다르면
틀린 답**이다 — 개수를 맞추지 않으면 답을 덜 낸 제출이 통과한다.

### `nan`·`inf` 는 숫자로 읽지 않는다

`NaN` 은 자기 자신과도 같지 않아 오차 비교가 뜻을 잃고, `inf` 는 차이가 늘 무한이다.
그런 출력은 **글자 그대로 같을 때만** 맞다.

지수 표기(`3.5e0`)는 받는다. 막으면 이 결정이 풀려던 "언어로 갈리는" 문제가 다시 생긴다.

## 기본값이 지금 동작이어야 한다

**이미 등록된 문제의 판정이 하나도 바뀌면 안 된다.** 컬럼 기본값도, 계약의 빈 값도
`EXACT` 다 — 이 필드가 없던 시절에 큐에 들어간 작업이 남아 있을 수 있다.

비교 방식은 **검증 지문**(`verificationSignature`)에도 들어간다. 판정을 바꾸는 값이므로,
빠뜨리면 오차만 고쳤을 때 정답 검증이 낡지 않은 것으로 남는다.

## 감수하는 것

- **오차를 잘못 넣으면 틀린 답이 통과한다.** 어드민 입력에 상한(0.1)을 두고, 오차 칸은
  실수 비교를 골랐을 때만 보인다. 그래도 0.1 은 큰 값이다 — 문제를 만드는 사람이
  무엇을 하는지 알아야 한다
- **스페셜 저지는 여전히 없다.** 답이 여러 개인 문제(정렬이 자유로운 출력 등)는 아직
  낼 수 없다. 그것은 채점기가 사용자 코드를 한 번 더 실행하는 일이라 훨씬 크다
