# ADR-0008. UI 컴포넌트 층으로 shadcn/ui 도입

- 상태: 채택
- 날짜: 2026-08-12

## 배경

이 저장소의 웹 런타임 의존성은 넷뿐이었다 — `next`, `react`, `react-dom`,
`@monaco-editor/react`. UI 는 `shared/ui` 에 직접 만들어 썼다.

그 방식이 처음 무너진 자리가 **선택기**다.

```tsx
export function Select({ className = "", ...props }: SelectHTMLAttributes<HTMLSelectElement>) {
  return <select {...props} className={`${CONTROL_CLASS} ${className}`} />;
}
```

테두리만 우리 것이고 **안은 운영체제 것**이다. 화살표 모양이 OS 마다 다르고, 열린
목록에는 우리 CSS 가 닿지 않는다. #206 으로 테마를 골라도 **드롭다운을 열면 그 선택이
무시된다** — 어둡게 골라 둔 화면에서 흰 목록이 떴다.

직접 만들 수도 있었다. 다만 접근성 있는 드롭다운은 초점 가두기·바깥 클릭·스크롤 잠금·
위치 뒤집기·타이핑 검색·키보드 전부를 포함한다. 그것을 한 번 겪고 나면 다음은 Dialog 이고
그다음은 Tooltip 이다(#288 이 `title=` 로 때운 자리, #133 이 손으로 만든 툴팁).

**한 컴포넌트를 만드는 문제가 아니라 컴포넌트 층을 갖는 문제**로 봤다.

## 결정

**shadcn/ui 를 UI 컴포넌트 층으로 쓴다.** 다만 세 가지는 우리 방식을 지킨다.

### 1. 다크 모드는 `light-dark()` 를 유지한다

shadcn 관례는 `:root` 에 라이트, `.dark` 에 다크 팔레트를 **두 벌** 적는 것이다.
우리는 #206 에서 한 벌로 정했다.

```css
--color-surface: light-dark(#ffffff, #12151b);
```

**컴포넌트가 실제로 요구하는 것은 그 이름의 변수가 있는 것뿐이다.** 값을 어떻게 고르는지는
상관하지 않는다. 그래서 관례를 따르지 않고 우리 것을 지켰다 — 팔레트를 두 벌 적으면
토큰이 늘 때 한쪽만 고쳐지는 자리가 다시 생긴다.

### 2. 토큰 이름은 갈아엎지 않고 **별명으로 잇는다**

```css
--color-background: var(--color-surface);
--color-foreground: var(--color-ink);
--color-primary: var(--color-brand);
```

모든 화면이 `text-ink`·`bg-surface` 로 적혀 있다. 이름을 바꾸면 이관(#291)이 색 이름
치환 작업으로 부풀고, 그 큰 diff 안에서 진짜 회귀가 묻힌다. 두 이름이 **같은 값**을
가리키므로 팔레트는 여전히 한 벌이다.

`ok`/`warn`/`danger`/`info` 와 `tier-*` 는 shadcn 에 대응이 없다. 우리 것으로 남는다.

### 3. `components.json` 의 별칭은 FSD 를 따른다

shadcn 기본값은 `components/ui` 지만 이 저장소는 `shared/ui` 다(#89). 별칭을 그쪽으로
잡아 `npx shadcn add` 가 올바른 자리에 넣게 한다.

## 함께 들어오는 것

| 패키지 | 왜 |
|---|---|
| `@radix-ui/react-select` | 동작(초점·키보드·위치)을 맡는다. 컴포넌트마다 하나씩 늘어난다 |
| `clsx` + `tailwind-merge` | `cn()`. **뒤에 온 클래스가 이기게** 만든다 — 없으면 `className` 이 기본값에 져서 `!important` 를 쓰게 된다 |
| `lucide-react` | shadcn 컴포넌트가 아이콘을 전제한다 |

아이콘을 손으로 그리는 쪽도 봤다(헤더 햄버거는 그렇게 했다). **복사해 온 컴포넌트를
고쳐 쓰면 upstream 과 멀어진다** — shadcn 의 값은 "가져와서 고칠 수 있다" 인데, 매번
아이콘 import 를 걷어내면 다음 갱신 때마다 같은 손질을 반복해야 한다.

## 감수하는 것

- **의존성이 넷에서 여덟로 늘었다.** 되돌리기 쉬운 결정이 아니다
- **네이티브 `<select>` 를 잃는다.** 폼 제출·검증이 공짜로 되던 것이 사라진다. 지금
  선택기는 전부 제어 컴포넌트(`value` + `onChange`)라 실제로 잃은 것은 없지만,
  `name` 으로 폼을 제출하는 화면을 새로 만들 수는 없다
- **모바일에서 OS 기본 선택기를 못 쓴다.** iOS·안드로이드의 휠 선택기는 대개 낫다.
  다만 화면 크기로 동작이 갈리는 컴포넌트를 두는 것이 더 나쁘다고 봤다
- 당분간 **shadcn 것과 손으로 만든 것이 섞인다.** #291 이 단계로 나눠 옮기며,
  그 기간을 짧게 가져가는 것이 그 이슈의 과제다

## 이관을 마치며 (#291)

옮긴 것: `Input`·`Textarea`·`Label`·`Badge`·`Alert`·`Select`·`Checkbox`·`Button`·`Card`·
`ConfirmDialog`·토스트, 그리고 **없어서 못 하던 것** — `Tooltip`·`DropdownMenu`.

**섞여 있던 기간이 이 이관의 진짜 비용이었다.** 단계로 나눈 덕에 각 PR 은 작았지만,
그동안 화면마다 shadcn 것과 우리 것이 함께 있었다. 그 기간을 짧게 가져가는 것이
#291 의 과제였고, 지금 끝났다.

## 남기는 것

`Table`(`Column` 추상 — #79·#193·#197), `EmptyState`(캐릭터를 고르는 것이 이 컴포넌트의
일이다 — #261), `CodeEditor`, `Markdown`, 브랜드 컴포넌트는 **우리 것으로 남는다.**
shadcn 에 대응이 없거나, 대응이 있어도 성격이 다르다.

여기에 둘을 더한다.

- **`Field`** — shadcn 의 `Form` 은 `react-hook-form` 을 전제한다. 그것을 들이면 지금
  폼 전부가 함께 바뀌고, **옮기는 변경과 고치는 변경이 한 diff 에 섞인다.** 이름표만
  `Label` 로 갈아 끼웠다
- **활동 그래프의 툴팁**(#133) — Radix 툴팁은 터치에서 뜨지 않고 그것이 옳다.
  그 화면은 휴대폰에서 자주 열리므로 **눌러서 여는** 지금 방식이 맞다
