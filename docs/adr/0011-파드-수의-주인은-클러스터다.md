# ADR-0011. 조정 대상의 파드 수는 클러스터가 주인이다

- 상태: 채택
- 날짜: 2026-08-13
- 관련: #418, #40(어드민 조정), #246(GitOps·selfHeal), #390(채점기 워커 수), #431

## 배경

**어드민에서 실행기를 늘리면 API 는 성공하는데 몇 분 뒤 되돌아온다.**

```
11:08:00  api    실행기 replica 를 3 로 조정했습니다: codekr-exec/codekr-executor
11:08:09  argocd sync Succeeded
4분 뒤    k8s    Scaled down codekr-executor from 3 to 2
```

ArgoCD Application 에 `selfHeal: true` 가 걸려 있고 차트가 `executor.replicas: 2` 를
선언하므로, **API 가 바꾼 값은 드리프트로 보여 되돌려진다.**

권한도 설정도 코드도 문제가 아니다 (#418 이 하나씩 지웠다). **명령형 조정과 선언형
관리가 같은 필드를 두고 부딪히는 것**이고, 그것은 둘 중 하나가 주인이 되어야 끝난다.

## 결정

**파드 수의 주인은 클러스터다.** ArgoCD 가 `spec.replicas` 를 보지 않게 한다.

```yaml
# oh-my-homelab 의 argocd Application
spec:
  ignoreDifferences:
    - group: apps
      kind: Deployment
      name: codekr-executor
      jsonPointers: ["/spec/replicas"]
    - group: apps
      kind: Deployment
      name: codekr-judge
      jsonPointers: ["/spec/replicas"]
    - group: apps
      kind: Deployment
      name: codekr-judge-contest
      jsonPointers: ["/spec/replicas"]
```

**차트의 `replicas` 는 처음 만들 때의 값**이 된다. 그 뒤로는 클러스터의 현재 값이
진실이고, 그것을 보는 곳은 `/admin/queues` 다.

## 왜 이쪽인가

**큐가 밀리는 순간에 손이 닿아야 한다.** 이 기능이 있는 이유가 그것이다(#40) — 적체는
어드민 화면에서 보이고, 같은 화면에서 바로 대응하지 못하면 화면은 계기판일 뿐이다.

나머지 둘은 그 자리에서 이것을 못 한다.

| 방법 | 왜 아닌가 |
|---|---|
| 파드 수 조정을 걷고 git 으로만 | 급할 때 커밋·sync 를 기다린다. 계기판만 남는다 |
| 어드민이 git 에 커밋 | **어드민 화면이 배포 저장소 쓰기 권한을 갖는다** (#348 이 같은 것을 걱정했다). 반영도 sync 주기만큼 느리다 |

HPA 를 쓰는 곳에서 흔히 하는 설정이기도 하다 — **파드 수를 밖에서 정하는 순간
`replicas` 는 선언의 대상이 아니다.**

## 대가

**git 만 봐서는 지금 몇 개가 도는지 알 수 없다.** 이것이 이 결정의 값이고, 숨기지 않는다.

- 배포 가이드가 "파드 수는 클러스터가 진실" 이라고 적는다
- 차트의 `replicas` 주석이 "처음 만들 때만" 이라고 적는다
- 어드민 화면이 "이 값은 배포로 되돌아가지 않습니다" 라고 말한다

**최소·최대 범위(1~8 같은)는 API 만 지킨다.** `kubectl scale` 로는 넘길 수 있다 —
그러나 그 권한은 이 화면보다 훨씬 큰 권한이므로, 거기까지 막는 것은 이 결정의 몫이
아니다. 범위는 **어드민 화면의 실수를 막는 장치**이지 클러스터의 정책이 아니다.

## 워커 수는 이 문제가 없다

#390 이 만든 채점기 **워커 수**는 Redis 에 있다. ArgoCD 가 볼 것이 없으므로 되돌려지지
않는다. 파드 수만 이 ADR 의 대상이다 — **프로세스가 스스로 자기 파드 수를 바꿀 수는
없기 때문이다.**

## 되돌리려면

`ignoreDifferences` 를 지우고 어드민 화면에서 파드 수 조정을 걷는다. 그때 남는 것은
워커 수 조정(#390)과 큐 모니터링(#13)이다.
