# 11. 웹 프론트엔드 구조 (Feature-Sliced Design)

새 코드를 어디에 둘지 판단하기 위한 문서다 (#89).

## 1. 계층

**위 계층은 아래 계층만 import 할 수 있다.** 반대 방향은 없다.

```
app/       Next.js 라우팅 전용. 화면을 조립하지 않고 views 를 렌더만 한다
  ↓
views/     화면 하나 = 라우트 하나
  ↓
widgets/   여러 feature 를 묶은 독립 블록
  ↓
features/  사용자가 하는 행위
  ↓
entities/  도메인 개념과 그 표현
  ↓
shared/    도메인을 모르는 것
```

**`pages` 대신 `views` 인 이유:** Next.js App Router 가 `app/` 을 쓰고 `pages/` 는
구 라우터 이름이라 혼동된다. FSD 의 `pages` 계층에 해당한다.

## 2. 무엇을 어디에 두는가

| 계층 | 판단 기준 | 지금 있는 것 |
|---|---|---|
| `shared` | **도메인을 몰라도 되는가?** | HTTP 클라이언트, 버튼·카드·입력, 날짜·용량 포맷터, 코드 에디터 |
| `entities` | **서버에 그 개념의 테이블이 있는가?** | problem, submission, user, activity, queue |
| `features` | **사용자가 하는 하나의 행위인가?** | auth, judge-stream, problem-editor, submission-explorer, executor-scale |
| `widgets` | **여러 feature 를 묶은 화면 블록인가?** | site-header, problem-tabs, solve-workspace |
| `views` | **라우트 하나에 대응하는가?** | problem-list, problem-solve, admin-queues … |
| `app` | 라우팅 | `page.tsx` 는 view 를 렌더만 한다 |

### 헷갈릴 때

- **entity 냐 feature 냐**: 명사면 entity, 동사면 feature.
  "제출"은 entity, "제출 목록을 필터링한다"는 feature.
- **widget 이냐 view 냐**: 다른 라우트에서도 쓸 수 있으면 widget, 아니면 view.
- **shared 에 둘까**: 도메인 타입을 import 해야 한다면 shared 가 아니다.

## 3. 슬라이스 구조

```
entities/problem/
  index.ts          ← 공개 API. 밖에서는 이것만 import 한다
  model/            타입, 라벨, 훅
  api/              서버 호출
  ui/               이 도메인의 표현 (TierBadge)
```

**슬라이스 내부 파일을 밖에서 직접 import 하지 않는다.** 그러면 내부를 고칠 때마다
남의 코드가 깨진다. 반대로 **슬라이스 안에서는 상대 경로**를 쓴다 —
자기 `index` 를 거치면 순환 참조가 된다.

## 4. 규칙은 ESLint 가 강제한다

`apps/web/eslint.config.mjs` 가 세 가지를 막는다.

| 위반 | 예 |
|---|---|
| 상위 계층 import | `entities` 가 `@/features/auth` 를 가져감 |
| 슬라이스 내부 직접 import | `@/entities/problem/ui/TierBadge` |
| shared 의 도메인 의존 | `shared` 가 `@/entities/user` 를 가져감 |

### 어드민 (#131)

- **인가는 `app/admin/layout.tsx` 한 곳**에 둔다. 페이지마다 감싸면 새 어드민 화면을
  만들 때 빠뜨릴 수 있고, 빠뜨린 사실은 아무도 눈치채지 못한다.
- 구획은 `widgets/admin-nav/model.ts` 의 **배열로 선언**한다. 항목 추가가 한 줄이다.
- 항목은 **역할로 감춘다.** 감추는 것은 안내이지 방어가 아니다 — 서버의 경로 규칙이
  최종 방어선이다. 그래도 감추는 이유는 눌렀을 때 403 이 나는 링크가 고장으로 보이기 때문이다.
- 어드민 화면은 `views/admin-*` 로 **평평하게 둔다.** 묶는 층을 만들지 않는다 —
  구획을 묶는 일은 내비게이션(widget)이 이미 하고 있고, 폴더를 한 겹 더 두면
  경로만 길어진다.
- 본문 폭은 `widgets/app-shell` 한 곳에서 정한다. **자식 레이아웃은 부모가 건 폭 제한을
  풀 수 없어서**, 폭을 정하는 자리를 위로 올렸다.
- 헤더는 어드민에서도 유지한다. 알림함(#106)과 로그아웃이 거기 있고, 사용자 화면으로
  돌아가는 길이기도 하다.

### 폼이 커질 때 (#127)

문제 편집 폼은 유형이 늘 때마다 커진다. 나누는 축은 **"유형이 늘어도 그대로인 것"** 이다.

| 파일 | 무엇 | 유형이 늘면 |
|---|---|---|
| `model/values.ts` | 값의 모양과 기본값 | 필드가 는다 |
| `ui/ProblemMetaFields` | slug·제목·분야·채점 방식·난이도·제한 | **그대로** |
| `ui/ProblemDescriptionFields` | 지문 | **그대로** |
| `ui/SqlSpecEditor` 등 | 유형별 입력 | 파일이 하나 는다 |
| `ui/ProblemForm` | 조립과 저장 | 분기 한 줄이 는다 |

**값의 모양과 그리는 일이 한 파일에 있으면 그 파일만 계속 자란다.** 그래서 값을 먼저 뗐다.

### 목록 화면의 필터 (#76)

필터가 많은 목록은 **칩 + 접기**로 푼다. 질의 DSL(GitHub·solved.ac 식)은 쓰지 않는다 —
전체 제출 목록을 보는 사람의 대부분은 한두 번 보고 마는데 그 사람에게 문법을 가르칠 수 없다.

| 규칙 | 왜 |
|---|---|
| 모든 입력에 **라벨** | placeholder 는 값을 넣으면 사라진다. 정작 값이 있을 때 무슨 필터인지 알 수 없다 |
| 자주 쓰는 것만 상시 노출 | 전부 밖에 두면 줄이 넘치고, 전부 안에 넣으면 흔한 조작에 클릭이 는다 |
| 걸린 필터는 **칩**으로 | 접어 둔 필터가 걸려 있어도 그 사실이 보여야 한다 |
| 칩은 **개별 제거** | 하나만 빼려고 전부 지우게 하지 않는다 |
| 칩은 **사람이 읽는 값** | `python:3.12` 가 아니라 `Python 3.12` |
| URL 에 담는다 | 새로고침·뒤로가기·링크 공유 후에도 같은 목록 |
| 빈 화면을 **둘로** | "아직 없다" 와 "조건에 맞는 것이 없다" 는 다른 말이고 할 일도 다르다 |

같은 계층의 다른 슬라이스는 **공개 API 로만** 쓴다. `entities/user` 가 실력 티어를
보여주려고 `@/entities/ranking` 의 타입을 가져가는 것은 허용된다 — 내부 파일이 아니라
index 를 통하기 때문이다 (#58).

**문서로만 적어두면 지켜지지 않기 때문에** lint 로 막는다. 플러그인은 새로 넣지 않고
ESLint 내장 `no-restricted-imports` 만 쓴다.

> ⚠️ `no-restricted-imports` 는 여러 config 객체에 나눠 쓰면 **뒤 객체가 앞 객체를 덮어쓴다.**
> 그래서 계층 규칙과 공개 API 규칙을 한 `patterns` 배열에 합쳐 두었다. 규칙을 추가할 때
> 새 config 객체를 만들지 말 것.

## 5. 서버 호출을 추가할 때

HTTP 클라이언트(`shared/api`)는 **도메인을 전혀 모른다.** 엔드포인트는 각 슬라이스가 가진다.

```ts
// entities/problem/api/index.ts
import { request } from "@/shared/api";

export const problemApi = {
  detail: (slug: string) => request<ProblemDetail>(`/api/v1/problems/${slug}`),
};
```

새 도메인이 생겨도 `shared/api` 는 그대로다.

## 6. 새 화면을 만드는 순서

1. `views/<이름>/ui/<이름>Page.tsx` 에 화면을 쓴다
2. `views/<이름>/index.ts` 로 내보낸다
3. `app/<라우트>/page.tsx` 는 그 view 를 렌더만 한다

```tsx
import { ProblemListPage } from "@/views/problem-list";

export default function Page() {
  return <ProblemListPage />;
}
```

**`app/` 에 화면 로직을 쓰지 않는다.** 라우팅과 화면이 섞이면 라우트를 바꿀 때
화면까지 건드려야 한다.

## 7. 공개 화면 목록은 한 곳에 있다 (#234)

`shared/config/routes.ts` 의 `PUBLIC_ROUTES` 를 **푸터와 `sitemap.xml` 이 함께 본다.**
화면이 늘었는데 한쪽만 고쳐지면, 링크는 있는데 색인이 안 되거나 그 반대가 된다.

```ts
export const PUBLIC_ROUTES = {
  풀기: [{ href: "/problems", label: "문제" }, …],
  둘러보기: [{ href: "/ranking", label: "랭킹" }, …],
};
```

**로그인해야 열리는 화면은 여기 넣지 않는다.** 눌렀을 때 로그인으로 튕기는 링크는
고장으로 보이고, 색인되면 검색 결과에서 로그인 화면이 나온다.

`sitemap.xml` 과 `robots.txt` 는 주소를 **요청의 Host 에서 만든다.** `NEXT_PUBLIC_*`
은 번들에 박히므로 주소를 넣으면 환경마다 이미지를 따로 빌드해야 한다 —
`shared/config` 가 API 주소를 같은 이유로 비워 두고 있다. 그래서 두 파일은 정적이
아니라 요청 시점에 만들어진다(`ƒ`).

**문제 상세도 sitemap 에 들어간다** (#271). 서버 전용 주소(`API_INTERNAL_BASE_URL`)로
공개 목록 API 를 부른다 — 어드민 API 를 부르면 미공개 문제가 새어 나간다.

그 값은 `shared/config/server.ts` 에 있고 **`server-only` 를 import 한다.** 클라이언트
컴포넌트가 실수로 가져다 쓰면 빌드가 깨진다 — 클러스터 내부 주소가 번들에 들어가면 안 된다.

**없으면 없는 대로 돈다.** 로컬·미리보기에는 그 값이 없고, API 를 못 불러도 고정 화면
7개는 그대로 나간다. 문제 목록을 못 받았다고 sitemap 전체가 비면 있던 화면마저 색인에서
빠진다.
## 8. 테마 (#206)

색은 `globals.css` 의 토큰 한 곳에서 나온다. 화면 코드는 테마를 모른다 — 예외는
**자기 색을 직접 정하는 것**뿐이고, 지금은 코드 에디터(Monaco) 하나다.

```css
--color-surface: light-dark(#ffffff, #12151b);
```

두 값을 한 줄에 적는다. 전에는 다크 팔레트가 `@media (prefers-color-scheme: dark)`
안에 따로 있었는데, **미디어 쿼리는 OS 가 정하는 것이라 사용자의 선택으로 이길 수
없다.** 지금은 `color-scheme` 이 어느 쪽을 쓸지 정하고, 그 값을 `:root[data-theme]`
이 바꾼다.

- 고르지 않으면 `color-scheme: light dark` → **OS 를 따른다** (자바스크립트 없이도 된다)
- 고르면 `data-theme` 이 붙고 그때부터 OS 를 보지 않는다
- `dark:` 유틸도 같은 두 갈래를 보도록 `@custom-variant dark` 를 다시 정의했다.
  토큰만 고치고 이것을 빠뜨리면 로고·티어 색만 OS 를 따라가 어긋난다

선택은 **기기(localStorage)에 두고, 로그인했으면 계정에도 올린다** (#206, #274).
로그인 없이도 되어야 하므로 기기가 먼저다.

- **로그인한 순간에는 계정 값이 이긴다.** 그 뒤 이 기기에서 고치면 양쪽이 함께 바뀐다.
  반대로 하면 새 기기에서 열 때마다 그 기기의 기본값이 계정 값을 덮어쓴다
- 계정 값을 받으면 **기기에도 적어 둔다.** 그러지 않으면 로그인할 때마다 화면이 한 번
  뒤집힌다 — 인라인 스크립트가 첫 그림 전에 읽는 것은 기기의 값뿐이다.
  적어 두면 **새 기기의 첫 방문 한 번**만 뒤집힌다
- 서버의 `null` 은 "고른 적 없음" 이다. 그때는 기기의 선택을 그대로 둔다 — 서버가
  모른다고 덮어쓰지 않는다

모델은 **`shared/theme` 에 둔다.** 코드 에디터(`shared/ui/CodeEditor`)가 고른 값을
알아야 하는데, `shared` 는 `features` 를 import 할 수 없다(§4 의 계층 규칙, ESLint 가
막는다). 토스트(`ToastProvider`)가 같은 이유로 `shared` 에 있다. `features/theme` 에는
**설정 화면의 선택 UI만** 남는다.

상태는 `useSyncExternalStore` 로 읽는다. 값이 리액트 바깥(localStorage·OS 설정)에
있기 때문이다. `useEffect` 로 맞추면 서버가 그린 값으로 한 번 렌더한 뒤 다시 렌더하게
되고, lint 도 그것을 막는다(`react-hooks/set-state-in-effect`).

번쩍임은 `<head>` 의 **인라인 동기 스크립트**로 막는다. 번들은 HTML 이 그려진 뒤에
실행되므로 거기서 바르면 밝은 화면이 한 번 보인다. 그 스크립트는 문자열이라 저장 키를
상수로 가져다 쓰지 못한다 — 두 곳이 어긋나지 않게 **시험이 지킨다**
(`theme.test.ts` 의 "스크립트가 같은 저장 키를 쓴다").

## 9. 좁은 화면 (#289)

**헤더만 접힌다.** 본문은 처음부터 폭에 따라 늘어나도록 짜여 있어서, 430px 에서
훑었을 때 넘치는 것이 헤더 하나뿐이었다(모든 화면이 가로로 550px 였고, 원인이 전부
같았다).

- 내비는 `lg`(1024px) 아래에서 감추고 **드로어**(`SideNav`)로 연다. 항목이 일곱 개라
  휴대폰 폭에 넣을 방법이 없다 — 전에는 글자가 세로로 쌓였다.
  **경계를 `md`(768) 로 두면 안 된다** — 로그인하면 어드민·알림·닉네임·설정·로그아웃이
  더 붙어 열 개가 넘고, 768px 에서 똑같이 무너진다. 비로그인으로만 재면 놓친다
- 목록 표는 **열을 감춘다**(`Table` 의 `Column.hideBelow`). 가로 스크롤은 존재를
  눈치채기 어렵고, 카드로 바꾸면 표를 쓴 이유(조밀함)가 사라진다
- 열을 감출 수 없는 표(대회 순위표처럼 문제 수만큼 열이 늘어나는 것)만
  `overflow-x-auto` + `min-w-[…]` 로 **스크롤**한다. `overflow-hidden` 이면 잘린다

### 드로어를 헤더 밖에 두는 이유

헤더에 `backdrop-blur` 가 걸려 있다. `backdrop-filter` 는 **자손 `position: fixed` 의
기준 상자를 자기 자신으로 바꾼다.** 헤더 안에 두었더니 화면을 덮어야 할 패널이 헤더
높이 안에 갇혔다 — 화면에는 띠 하나만 보였다.

새 고정 오버레이를 만들 때 같은 함정이 있다. **필터가 걸린 조상 안에 두지 않는다.**


## 10. UI 컴포넌트 (#287)

프리미티브는 **shadcn/ui** 기반이다 (ADR-0008). 손으로 만들던 것에서 옮기는 중이라
당분간 두 벌이 섞여 있다 — 이관은 #291 이 단계로 나눠 한다.

- `components.json` 의 별칭이 `shared/ui`·`shared/lib` 를 가리킨다. `shadcn add` 가
  FSD 자리에 넣는다
- shadcn 이 기대하는 색 이름(`background`·`foreground`·`primary`…)은 `globals.css` 에서
  **우리 토큰의 별명**으로 이어 두었다. 화면은 계속 `text-ink`·`bg-surface` 로 적는다
- `cn()`(`shared/lib`)으로 클래스를 합친다. `tailwind-merge` 가 있어야 `className` 으로
  넘긴 값이 컴포넌트 기본값을 이긴다
- 복사해 온 컴포넌트는 **upstream 과 가깝게 둔다.** 색 이름을 우리 것으로 바꿔 적지
  않는 이유가 그것이다 — 다음 갱신 때 그대로 가져올 수 있어야 한다

### 폼을 화면에서 나누는 축 (#337)

`docs/11` 의 "폼이 커질 때(#127)" 는 **파일을 나누는 축**을 적었다. 화면을 나누는 축은
이렇다 — 문제 폼은 일곱 덩어리다.

| 구획 | 공개에 필요한가 | 언제 사라지는가 |
|---|---|---|
| 기본 정보 · 지문 | 필요 | 없음 |
| 출제 정보 (#236) | 선택 | 없음 |
| 테스트케이스 | 필요 | **SQL 유형이면** |
| SQL 스키마와 정답 | 필요 | **stdio 유형이면** |
| 언어별 제한 · 초기 코드 · 정답 코드 | 선택 | 없음 |

**탭이 아니라 접이식이다.** 탭은 셋을 잃는다 — 오류가 어느 구획에 있는지 보이지 않고,
저장 전에 전체를 훑을 수 없고, AI 초안(#230)이 여러 구획을 채울 때 어디가 채워졌는지
알 수 없다. 접이식은 **모든 구획이 늘 마운트되어 있어** 열고 닫아도 값이 사라지지 않는다.

**등록과 수정은 껍데기만 다르다.** 처음 만들 때는 순서가 도움이 되므로 전부 펴 두고,
고칠 때는 방해가 되므로 접어서 목차로 쓴다 — 차이는 `defaultOpen` 하나다.
**구획 컴포넌트와 검증·저장은 한 벌**이고, 갈라지면 "등록에서는 되는데 수정에서는
안 되는" 것이 생긴다. 대회 폼(#335)도 같은 방식을 따른다.

### 옮긴 것과 남은 것

| 옮김 (shadcn 기반) | 아직 안 옮김 | **안 옮긴다** |
|---|---|---|
| `Input`·`Textarea`·`Label`·`Badge`·`Alert`·`Select`·`Checkbox`·`Button`·`Card`·`ConfirmDialog`·토스트·**`Tooltip`** | `DropdownMenu` | `EmptyState`·`Table`·`CodeEditor`·`Markdown`·브랜드·**활동 그래프의 툴팁** |

`Field` 는 **우리 것으로 남되 이름표만 `Label` 로 갈아 끼웠다.** shadcn 의 `Form` 은
`react-hook-form` 을 전제하는데, 그것을 들이면 지금 폼 전부가 함께 바뀐다 —
**옮기는 변경과 고치는 변경이 한 diff 에 섞인다.**

**"아직 안 옮김" 과 "안 옮긴다" 는 다른 말이다.** 오른쪽 칸은 대응하는 shadcn 부품이
없거나, 있어도 **성격이 다르다.**

- `Table` — 우리 것은 `columns` 배열을 받아 그리는 **데이터 주도** 부품이다
  (`hideBelow`·`href`·`align`·`render`, #79·#193·#197). shadcn 의 `Table` 은
  `<table>` 을 감싼 **표현용**이라, 그 위에 우리 추상을 다시 얹어야 한다 — 얻는 것보다
  잃는 것이 크다
- `EmptyState` — 캐릭터를 고르는 것이 이 부품의 일이다 (#261)
- `CodeEditor`·`Markdown`·브랜드 — 대응하는 것이 아예 없다

### 툴팁 (#291 4단계)

**`title=` 을 걷는다.** 브라우저 기본 툴팁은 세 가지를 못 한다 — 1초 넘게 걸리고,
모양·위치를 손댈 수 없고, **키보드로 닿지 않는다.** 아이콘만 있는 버튼의 뜻을 그것으로
알리면 마우스를 쓰지 않는 사람에게는 뜻이 없다.

**이름은 `aria-label` 이 맡는다.** 툴팁은 보이는 설명이고, 스크린 리더는 시각적 툴팁을
읽지 않는다 — 둘은 다른 일이다.

**활동 그래프의 칸(#133)은 옮기지 않는다.** Radix 툴팁은 **터치에서 뜨지 않는다** —
터치에는 hover 가 없어 툴팁을 띄우려면 탭을 가로채야 하고, 그러면 버튼이 눌리지 않는다.
그 칸은 터치에서도 떠야 하고(#133 이 그것을 요구했다), `overflow-x-auto` 안에서 잘리지
않게 붙는 쪽을 부모가 정한다(#312). **얻는 것보다 잃는 것이 크다.**

### 버튼 (#291 2단계)

variant 넷(`primary`/`secondary`/`ghost`/`danger`)을 **이름까지 그대로 뒀다.**
shadcn 기본 이름으로 바꾸면 58개 파일이 함께 바뀌고, 옮기는 변경과 고치는 변경이
한 diff 에 섞인다.

**바뀐 것은 클래스 병합이다.** `cn`(tailwind-merge)을 거치므로 `className` 으로 준
값이 실제로 이긴다. 전에는 반만 이겼다 — 같은 버튼에 `px-4 py-2 text-sm`(기본)과
`px-3 py-1 text-xs`(덮어쓰기)가 둘 다 실려서, **글자 크기는 작아지고 여백은 그대로**
였다. 크기를 덮어쓰는 곳이 스물두 자리쯤 되고, 그것들이 이제 의도한 크기로 그려진다.

**링크는 `asChild` 로 적는다** (#376).

```tsx
<Button asChild>
  <Link href="/problems">문제 풀러 가기</Link>
</Button>
```

전에는 링크가 버튼을 감싸서 `<a><button>` 이 그려졌다 — **`<a>` 는 인터랙티브 요소를
담을 수 없다.** 브라우저가 알아서 처리해 주므로 눈으로는 멀쩡해 보이고, 보조 기술에서만
두 겹으로 읽힌다. 서른 자리가 그랬다.

`asChild` 는 Radix 의 `Slot` 이다 — 자식이 **정확히 하나**여야 하고, 둘이면 던진다.

`Badge`·`Alert` 의 tone 다섯(`ok`/`danger`/`warn`/`info`/`muted`)은 **그대로 유지한다.**
이 저장소의 뱃지는 판정과 상태를 말한다 — `tone="destructive"` 라고 적으면 "오답" 보다
멀어진다.

### 상자 (#291 3단계)

**shadcn 의 `Card` 를 그대로 가져오지 않았다.** 그쪽 기본은
`flex flex-col gap-6 py-6 rounded-xl shadow-sm` 인데, 이 저장소의 상자 마흔일곱 자리는
전부 자기 여백과 배치를 `className` 으로 준다 — `p-5`, `space-y-3`,
`grid grid-cols-2`, `divide-y p-0`.

그 기본을 들이면 **마흔일곱 화면의 배치가 한꺼번에 바뀐다.** `p-5` 는 tailwind-merge 가
정리하지만 `flex`·`gap` 은 정리 대상이 아니라 그대로 얹힌다.

그래서 **평평한 상자를 유지한다.** 얻은 것은 `cn` 클래스 병합과 `data-slot` 이다.

`CardHeader`·`CardContent` 도 두지 않는다 — 평평한 상자에서 그것들은 아무 일도 하지
않는 감싸개다.

**`CardTitle` 만 뒀다.** `text-sm font-semibold text-ink` 가 **스물여섯 자리에 그대로
적혀 있었고**, 제목 크기를 한 번 바꾸는 일이 스물여섯 곳을 고치는 일이었다.
`div` 가 아니라 **`h2`** 로 그린다 — 이 자리들은 실제로 구역 제목이고, 스크린 리더가
문서를 훑을 때 목차가 된다.

### 토스트 (#112, #134, #291 5단계)

띄우는 쪽은 `useToast().success(…)` **그대로다.** 안에서 sonner 가 돈다는 것을 스물아홉
개 화면이 알 필요가 없고, 그래서 이 이관이 화면을 하나도 건드리지 않았다.

**모양은 우리가 정한다** (`unstyled`). sonner 기본을 쓰면 색 토큰(`ok`/`danger`/`info`)과
어긋나고 라이트·다크가 따로 논다. 자리·쌓임·손짓만 맡긴다.

`#134` 가 정한 것들은 클래스가 아니라 **설정**이 되었고, `overlay.ts` 한 곳에 남는다 —
우측 하단, 셋까지, 5초, 최대 폭 24rem. `overlay.test.ts` 가 그것을 계속 시험한다.

**Provider 가 없어졌다.** 띄우는 함수가 전역이라 Provider 밖에서 불러도 터지지 않는다 —
전에 폴백을 따로 둬서 지키던 성질이 이제 구조에서 나온다.

옮기면서 얻은 것:

| | 전 | 후 |
|---|---|---|
| 읽는 동안 | **5초가 지나면 사라졌다** | 마우스를 올리면 멈춘다 (7초 뒤에도 남아 있는 것을 확인) |
| 탭이 가려져 있을 때 | 시간이 흐른다 | 멈춘다 |
| 터치 | 닫기 버튼만 | 밀어서 닫는다 |
| 키보드 | DOM 끝까지 탭해야 닿는다 | `⌥T` 로 간다 |

`aria-live="polite"` 는 그대로다 — `assertive` 는 읽고 있던 내용을 끊는데, 토스트는
대개 그만큼 급하지 않다.

### 마크다운 편집기 (#388)

게시글·질문 본문은 `MarkdownEditor` 로 쓴다 — 버튼(굵게·코드·코드 블록·목록·제목)과
미리보기가 함께 온다.

**편집기 라이브러리를 들이지 않았다.** 들이면 그리는 쪽이 둘이 된다 — 편집기의
미리보기와 우리 `Markdown`. **둘이 다르게 그리면 미리보기가 거짓말이 되고**,
`isSafeUrl`(#137)을 안 거치면 **작성자만 다른 것을 본다.**

작성 칸은 그대로 두고 버튼과 미리보기만 붙였다. 새 의존성이 없으므로 지연 로딩도
필요 없고, 라이트·다크·좁은 화면은 우리 부품이 이미 하던 대로 따라온다.

**버튼이 글자에 무엇을 하는지는 `editorCommands.ts` 에 순수 함수로 있다.** 커서 자리를
다루는 코드는 눈으로 읽어서 맞는지 알 수 없다 — 실제로 그 시험이 결함을 하나 잡았다
(선택이 줄 첫머리에서 끝날 때 안 고른 줄까지 목록이 되던 것).

댓글에는 넣지 않는다. 한두 줄짜리에 도구 모음은 과하다.

### 코드 블록 색 (#384)

마크다운의 코드 블록은 **언어에 맞게 칠한다.** 에디터(Monaco)는 색이 있는데 읽는
자리만 회색이면, 코드를 읽는 사이트에서 코드가 가장 안 읽힌다.

**하이라이터를 고른 기준은 성능이 아니라 안전이었다.** `Markdown`(#137)은
`dangerouslySetInnerHTML` 을 쓰지 않는다 — 이 저장소에서 가장 오래된 안전 규칙이고,
여기서 새는 구멍은 게시글·댓글·질문에 그대로 이어진다.

Shiki·highlight.js 는 **HTML 문자열**을 돌려준다. 쓰려면 그 규칙을 깨야 한다.
`prism-react-renderer` 는 **토큰 배열**을 돌려주므로 React 엘리먼트로 그릴 수 있다.

| 판단 | 결정 |
|---|---|
| 무엇으로 | `prism-react-renderer` — 토큰을 돌려준다 |
| Shiki 를 안 쓴 이유 | HTML 문자열, 그리고 비동기 초기화 동안 코드가 회색으로 남았다 칠해진다 |
| 모르는 언어 | **칠하지 않고 그대로 둔다.** 언어를 안 적은 블록이 대부분이다 |
| 라이트·다크 | `useTheme()` 의 값으로 고른다 (#206 과 같은 규칙) |
| 제출 상세의 코드 | 손대지 않았다 — 읽기 전용에 에디터를 띄우는 것은 무겁다 |

**이름 표는 명시적이다.** 아무 문자열이나 Prism 에 넘기면 문법을 못 찾고, 그때 블록이
통째로 비는 경우가 있다 — 안 칠해지는 것보다 나쁘다.

### 되묻기 (#291 4단계)

되돌릴 수 없는 일을 하기 전에 묻는 자리는 **`ConfirmDialog`** 다. `confirm()` 을 쓰던
세 자리(글 삭제·댓글 삭제·문제 삭제)가 여기로 왔다.

브라우저 기본 대화상자가 못 하는 것:

- **모양을 손댈 수 없다.** 무엇이 지워지는지 따로 설명할 자리가 없다
- **자바스크립트를 멈춰 세운다.** 그동안 화면은 아무것도 못 하고, 자동화된 확인도
  불가능하다 (`prompt()` 를 걷었던 것과 같은 이유)

`Dialog` 가 아니라 **`AlertDialog`** 인 이유: 바깥을 눌러도 닫히지 않고, 스크린 리더에
`alertdialog` 로 알려지며, 확인·취소가 반드시 있다.

정한 것 둘:

- **취소가 먼저 놓이고, 열 때 포커스도 취소에 간다.** 되돌릴 수 없는 일에서 손이 먼저
  가는 자리에 위험한 버튼을 두지 않는다
- **누르는 동안 닫지 않는다.** 서버가 거절하면 그 자리에서 알아야 한다

`Tooltip`·`DropdownMenu` 는 **아직 들이지 않았다.** 이유는 아래에 적는다.

#### 활동 그래프의 툴팁을 Radix 로 옮기지 않은 이유 (#133)

`ActivityCell` 은 툴팁을 손으로 만들었다. Radix `Tooltip` 으로 옮기면 잘림(#312)과
위치 계산을 공짜로 얻지만, **터치에서 뜨지 않는다** — Radix 의 툴팁은 hover·focus
전용이고, 터치 사용자를 위해서는 `Popover` 를 쓰라고 그쪽 문서가 말한다.

지금 것은 `onClick` 으로 토글해서 **터치에서도 뜬다.** 그것이 `title` 을 버리고 손으로
만든 이유였다. 옮기면 그 결정이 되돌려진다 — 얻는 것보다 잃는 것이 크다.

### 선택기

`Select` 는 `<option>` 자식을 그대로 받는 **호환 층**(`SelectField`)이다. 네이티브
`<select>` 를 쓰던 열 곳 남짓을 이 PR 에서 함께 고치지 않으려고 뒀다 — 무엇이 깨졌을 때
선택기 때문인지 화면을 고쳐서인지 갈라야 한다. 새 화면은 `SelectRoot`/`SelectItem` 을
직접 쓰고, 부르는 쪽이 모두 옮겨간 뒤 이 층을 지운다.

**Radix 는 빈 문자열을 항목 값으로 받지 않는다.** 우리 화면들이 "조건 없음" 을
`<option value="">전체</option>` 로 쓰고 있어서, 호환 층이 안에서 바꿔치기한다.

### 체크박스 (#318)

`CheckboxField` 는 **`Field` 와 따로 둔다.** 두 가지가 다르다.

- **모양**: `Field` 는 이름표가 위에 오고 체크박스는 옆에 온다. 한 부품으로 둘 다
  하려면 방향 옵션이 생기고, 그 옵션은 부르는 쪽마다 다르게 쓰인다
- **감싸기**: `<label>` 로 감싸면 그 안의 `<button>`(Radix 의 체크박스가 그것이다)이
  **한 번의 탭에 두 번 활성화**될 수 있다 (#306 에서 선택기가 겪은 것).
  둘 다 `htmlFor`/`id` 로만 잇는다

`<input type="date">` 는 그대로 둔다. 날짜 선택기는 훨씬 큰 물건이고
(`Calendar` + `Popover` + `react-day-picker`), **네이티브 쪽이 모바일에서 낫다.**

## 10.1 파일이 여럿인 문제의 편집 화면 (#457, #498)

`runtimes[].files` 가 비어 있지 않으면 **에디터 위에 탭이 뜬다.**

- **초안은 파일마다 따로 저장한다** (`codekr.draft.{slug}.{runtimeId}.{파일이름}`).
  한 칸에 모으면 문제가 파일 목록을 고쳤을 때 그 칸 전체가 못 읽는 값이 되고, 그러면
  **친 코드가 통째로 사라진다.** 파일마다면 이름이 살아 있는 것만 남는다
- 키에 런타임이 들어가는 이유는 #383 과 같다 — 언어를 바꾸면 파일 이름이 갈린다
- **고칠 수 없는 파일도 보여 준다.** 감추면 "왜 이 함수가 있는지" 를 알 수 없고 그것을
  읽는 것이 문제의 절반이다. 대신 자물쇠를 붙이고 에디터를 읽기 전용으로 둔다
- **제출에는 고칠 수 있는 파일만 싣는다.** 서버가 나머지를 문제의 것으로 채운다(#497)
- **실행(`/run`)은 막는다.** 서버가 아직 파일 하나만 받으므로, 조용히 한 파일만 돌리면
  "실행은 되는데 제출은 다른 결과" 가 되어 무엇을 믿을지 알 수 없다

### 오류를 파일·줄로 되돌린다

컴파일 오류가 `Helper.java:17` 이라고 나오면 **그 파일이 어느 탭인지** 알려 준다.
누르면 `?file=Helper.java` 로 풀이 화면이 열리고 그 탭이 먼저 뜬다.

오류 문자열의 모양은 언어마다 다르다 (`Helper.java:17:`, `File "helper.py", line 3`,
`helper.cpp:5:1:`, `./helper.go:4:6:`). **모양을 다 아는 척하지 않는다** — 우리가 아는
것(이 문제의 파일 이름)을 문자열에서 찾고 그 뒤의 첫 숫자를 줄 번호로 본다.
**못 찾으면 아무 말도 하지 않는다**: 틀린 자리를 가리키면 사용자가 멀쩡한 줄을 고친다.

## 11. 화면 메타데이터 (#277, #278)

접미는 **루트에서 한 번만** 붙인다.

```ts
title: { default: "코드.kr — …", template: "%s · 코드.kr" }
```

화면은 `title: "문제"` 처럼 자기 이름만 적는다. 전에는 화면마다 "· 코드.kr" 을 적어
두어, 사이트 이름을 바꾸면 서른 곳을 고쳐야 했다(그리고 절반은 아예 빠져 있었다).

- **색인은 메타로 막는다.** `robots.txt`(#234)는 크롤링을, `robots: { index: false }` 는
  색인을 막는다 — 다른 층이다. 어드민·설정·알림·내 제출·로그인·편집 화면이 그 대상이다
- **문제 상세의 네 탭은 하나의 정본**(`/problems/{slug}`)을 가리킨다. 탭은 같은 문제를
  다른 각도로 보는 것이지 다른 문서가 아니다
- 절대 주소의 기준은 `metadataBase` 이고 값은 **퓨니코드**다 (ADR-0009).
  `SITE_ORIGIN` 은 **빌드 시점에 박힌다** — 컨테이너 환경 변수로는 바뀌지 않는다

**문제 제목을 메타데이터에 넣는 것은 아직 못 한다.** 서버가 API 를 부를 주소를
모른다 (#271). 주소만으로 만들 수 있는 것(정본 주소)까지만 해 두었다.
