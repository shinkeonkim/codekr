## 사용자가 말한 것

$ARGUMENTS

비어 있으면 **무엇을 만들고 싶은지 먼저 묻는다.** 추측해서 이슈를 만들지 않는다.

---

## 1. 무엇을 말한 것인지 먼저 파악한다

사용자는 대개 **증상**이나 **바람**을 말한다. 그대로 제목으로 옮기지 말고, 코드를 확인해
**무엇을 바꾸는 일인지** 알아낸다.

```bash
# 관련 코드 찾기 — 어느 계층의 일인지부터 확인
rg -l "<핵심어>" apps/ libs/ --type-add 'kt:*.kt' --type-add 'go:*.go'
```

확인할 것:

- **이미 되어 있는가?** 구현돼 있는데 화면에 안 나오는 것뿐일 수도 있다
- 어느 앱의 일인가 (api / web / executor / judge / infra)
- **API 변경이 필요한가.** 화면만 고치면 되는지, 서버까지 가는지에 따라 크기가 다르다
- 관련 문서가 있는가 (`docs/`, `docs/adr/`, `docs/plans/`)

> 여기서 "이미 되어 있다"가 나오면 **이슈를 만들지 말고 그 사실을 알린다.**
> 실제로 그런 경우가 있었다 (#82).

## 2. 중복을 확인한다 — 이슈를 만들기 전에 반드시

```bash
# 열린 것과 닫힌 것 모두 본다. 닫힌 이슈는 "왜 안 했는지" 를 알려준다.
gh issue list --state all --limit 100 --json number,title,state,labels \
  -q '.[] | "#\(.number) [\(.state)] \(.title)"'

# 본문까지 검색
gh search issues --repo shinkeonkim/codekr "<핵심어>" --limit 20 \
  --json number,title,state -q '.[] | "#\(.number) [\(.state)] \(.title)"'
```

| 상황 | 할 일 |
|---|---|
| 같은 이슈가 열려 있다 | **새로 만들지 않는다.** 그 이슈에 내용을 덧붙일지 묻는다 |
| 비슷하지만 다르다 | 새로 만들되 **본문에서 그 이슈를 참조**하고 차이를 적는다 |
| 닫힌 이슈가 있다 | 왜 닫혔는지 확인한다. 다시 열 일인지, 새 이슈인지 판단한다 |
| 큰 이슈의 일부다 | 쪼갤지 그 이슈에 넣을지 묻는다 |

**애매하면 사용자에게 묻는다.** 중복 이슈는 나중에 둘 다 반쯤 하다 만다.

## 3. 크기를 정한다

한 이슈 = **한 PR 로 끝낼 수 있는 크기**여야 한다. 그보다 크면 쪼갠다.

쪼개는 기준은 파일 수가 아니라 **따로 리뷰·머지할 수 있는가**이다.

- "API 만들고 화면도 붙인다"는 대개 한 이슈여도 된다 (같이 있어야 동작한다)
- "SQL 문제 유형을 지원한다"는 여러 이슈다 (스키마 → 채점기 → 어드민 → 사용자 화면)
- **리서치가 필요하면 리서치를 별도 이슈로** 두는 것도 좋다 (#76, #86 이 그렇다)

## 4. 이슈를 쓴다

```bash
gh issue create --title "[영역] 무엇을" --label "area:...,type:...,mvp|post-mvp" --body "..."
```

| 라벨 | 값 |
|---|---|
| 영역 | `area:api` `area:web` `area:executor` `area:judge` `area:infra` `area:docs` |
| 종류 | `type:feature` `type:chore` `bug` `documentation` `enhancement` |
| 시점 | `mvp` `post-mvp` |

본문에 담을 것:

1. **왜** — 지금 무엇이 문제인가. 사용자가 말한 증상을 그대로 옮기지 말고,
   **그것이 왜 문제인지**를 쓴다
2. **할 일** — 체크리스트
3. **판단이 필요한 지점** — 답을 정하지 못한 것을 숨기지 않는다.
   "A 와 B 중 무엇" 을 적어 두면 구현할 때 다시 생각하게 된다
4. **완료 조건** — 무엇이 되면 끝인가
5. **관련** — 참조하는 이슈·문서

**쓰지 말 것:** 구현 방법을 처음부터 끝까지 적는 것. 이슈는 명세서가 아니다.
지금 아는 것과 정해야 할 것을 구분해 두는 것으로 충분하다.
