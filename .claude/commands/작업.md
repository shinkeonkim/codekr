`docs/10_작업_방식.md` 의 규칙에 따라 작업한다. 그 문서를 먼저 읽고 시작할 것.

## 지금 할 일

$ARGUMENTS

인자가 비어 있으면, 열린 이슈와 스택 상태를 먼저 보여주고 **무엇부터 할지 물어본다.**

## 시작할 때 반드시 확인할 것

```bash
gh issue list --state open --limit 40 \
  --json number,title,labels -q '.[] | "#\(.number) \(.title)  [\([.labels[].name] | join(","))]"'

gh pr list --state open --json number,headRefName,baseRefName \
  -q '.[] | "#\(.number) \(.headRefName) -> \(.baseRefName)"'

git branch --show-current && git status --short
```

## 지켜야 할 것

- **이슈 없이 작업하지 않는다.** 없으면 먼저 만든다
- 브랜치는 **바로 앞 스택 브랜치**에서 딴다. main 이 아니다
- 커밋 메시지에 이슈 번호(`(#N)`)를 단다
- PR 의 base 는 **바로 앞 스택 브랜치**, 본문에 `Closes #N`
- **검증하지 않은 것을 했다고 쓰지 않는다.** PR 본문에는 실제로 돌린 명령과 결과만
- 지금 PR 범위를 넘는 문제를 발견하면 **고치지 말고 이슈로 남긴다**
- 파일 200줄 상한
- `git push --force` 금지. `--force-with-lease` 만

## 끝낼 때

- 관련 문서를 같이 고쳤는지 확인 (`docs/10_작업_방식.md` §7)
- PR 본문에 **하지 않은 것과 그 이유**를 적었는지 확인
