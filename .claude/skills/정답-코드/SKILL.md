# 정답 코드 쓰기 (#481)

**정답 코드가 없으면 문제가 맞는지 확인할 수 없다.** 그리고 그 코드는 두 가지를 한다.

1. **문제가 풀린다는 증거** — 제약 안에서 시간·메모리 제한을 지키며 돈다
2. **기대 출력을 만드는 근거** — 테스트케이스의 정답이 어디서 왔는지

둘째가 특히 크다. **입력만 있고 정답이 없으면 테스트케이스가 아니다.**

## ⚠️ 저장소에 커밋하지 않는다

정답 코드는 **테스트케이스보다 더** 새면 안 되는 것이다. `.problem-drafts/` 안에만 쓴다 —
그 폴더는 `.gitignore` 되어 있다. 이유는 `문제-초안` 스킬에 적힌 것과 같다 (#424).

## 1. 초안을 읽는다

`.problem-drafts/{slug}/problem.json` 에 제약·형식·정답 범위가 있다. 없으면 **먼저
`문제-초안` 스킬로 채운다** — 제약을 모르면 어떤 복잡도로 써야 하는지 알 수 없다.

## 2. 코드를 쓰기 전에 **의도한 복잡도**를 말한다

이것이 이 스킬이 "그냥 코드를 써 주는 것" 과 다른 점이다.

```
N ≤ 100,000 이고 값이 10^9 까지 → O(N log N). 정렬 후 투 포인터.
합이 10^14 까지 가므로 64비트.
```

- **제약이 `N ≤ 10^6` 인데 `O(N^2)` 이면 정답이 아니다.** 돌아가는 코드일 뿐이다
- 반대로 필요 이상으로 어려운 풀이를 쓰면 **문제의 난이도가 지문과 어긋난다**
- 복잡도를 먼저 말하면 사용자가 **여기서** 고칠 수 있다. 코드를 다 쓴 뒤에는 늦다

## 3. 언어를 고른다

- **문제가 언어를 제한하면**(#419) 그 언어여야 한다
- 제한이 없으면 **파이썬**을 기본으로 한다. 읽기 쉽고 이 저장소의 시드가 그렇다
- 다만 제약이 큰 문제(`N ≥ 10^6`, 무거운 반복)는 파이썬이 시간 제한에 걸릴 수 있다 —
  그때는 **제한을 늘릴지, 언어를 바꿀지**를 사용자에게 묻는다. 몰래 정하지 않는다
- 아희·엄랭(#394) 같은 느린 런타임은 그 자체로 5초를 쓴다 (#97 의 런타임별 제한)

## 4. **직접 돌려 본다**

돌려 보지 않은 코드는 증거가 아니다. 사람이 눈으로 읽어 맞다고 한 코드가 틀린 경우를
이 저장소는 이미 겪었다.

```bash
# 예제와 경계로 직접 돌린다. 결과를 눈으로 확인한다.
echo "1 2" | python3 .problem-drafts/{slug}/solution.py
```

돌려 볼 것:

- 지문의 **예제 전부**
- **경계** — `N=1`, 최댓값, 최솟값, 음수, 0, 빈 입력(허용된다면)
- **가장 큰 입력** — 시간이 제한 안에 들어오는지. 큰 입력은 만들어서 잰다

출력 형식도 함께 본다. **채점은 문자열 비교다** — 공백 하나, 줄바꿈 하나가 오답이다.

## 5. 기대 출력을 채운다

돌린 결과를 `testcases/{seq}.out` 에 넣는다. **손으로 적지 않는다** — 손으로 적은 값은
근거가 없고, 틀리면 맞는 풀이가 떨어진다.

그리고 `problem.json` 의 `solution` 자리에 정답 코드를 넣는다. 어드민이 그것으로
**전체 테스트케이스를 다시 돌려 본다** (#39).

## 6. 끝내며 알린다

- 의도한 복잡도와 **왜 그것인지**
- 무엇으로 돌려 봤고 무엇을 확인했는지 (예제·경계·최대 입력의 실측 시간)
- 확인하지 못한 것 — 그것을 적지 않으면 확인한 것처럼 읽힌다
