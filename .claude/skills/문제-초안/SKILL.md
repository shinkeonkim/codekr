# 문제 초안 만들기 (#480)

**문제를 만드는 일의 대부분은 글쓰기가 아니라 빠진 것을 찾는 일이다.**

머릿속의 아이디어는 대개 이 정도다 — "두 배열을 합쳐서 정렬하는 문제". 그것을 실제
문제로 만들려면 정해져야 하는 것이 여럿이고, **사람은 그것을 자주 빠뜨린다.** 빠뜨린 채로
등록하면 나중에 오류 신고(#478)로 돌아온다: "테스트케이스가 빠졌다", "제약 조건이 안 적혀 있다".

## ⚠️ 만든 것을 저장소에 커밋하지 않는다

**이 저장소는 public 이다.** 문제 초안에는 **테스트케이스와 정답**이 들어간다 — 그것이
커밋되면 **문제가 무너진다.** 그리고 한 번 public 에 들어가면 되돌릴 수 없다 (#424).

그래서 산출물은 **`.problem-drafts/` 안에만** 쓴다. 그 폴더는 `.gitignore` 되어 있다.

- 이 폴더 **밖에 문제 파일을 쓰지 않는다**
- 초안을 커밋하지 않는다. `git add` 를 부르지 않는다
- 사용자가 "저장소에 넣어 달라" 고 해도 **왜 안 되는지 말하고 멈춘다** — 규칙만 있으면
  언젠가 깨지므로, 그 이유를 매번 말하는 것이 이 문서가 하는 일이다

## 1. 먼저 되묻는다

아이디어를 받으면 **바로 만들지 않는다.** 아래를 확인하고, 정해지지 않은 것을 모아
**한 번에** 묻는다 (하나씩 물으면 대화가 길어진다).

### 제약 조건 — 없으면 난이도가 정해지지 않는다

- `N` 의 범위. `10^5` 과 `10^9` 는 다른 문제다 (`O(N log N)` 인가 `O(log N)` 인가)
- 값의 범위. 음수가 있는가, 0 이 있는가
- **정답의 범위.** 32비트를 넘는가 — #280 이 사칙연산 넷에서 통째로 다룬 것이 이것이다

### 입출력 형식 — 채점이 문자열 비교다

- 몇 줄에 무엇이 오는가. 공백인가 줄바꿈인가
- 출력이 여러 줄인가. 마지막 줄에 줄바꿈이 있는가
- **정답이 여럿인가.** 그렇다면 스페셜 저지(#452)가 필요하다 — 그것은 다른 일이므로
  여기서 결정만 하고 알린다

### 경계 — 여기서 빠진 것이 나중에 신고가 된다

`N=1`, 빈 입력, 최댓값, 최솟값, 음수, 0, 중복, 전부 같은 값, 이미 정렬된 것, 역순.

**문제마다 해당하는 것이 다르다.** 목록을 그대로 읊지 말고, 이 문제에서 **뜻이 달라지는
것**만 고른다.

### 유형 — 무엇으로 채점하는가

| 유형 | 정하는 것 |
|---|---|
| `JUDGE_STDIO` | 기본. 위의 것들 |
| `JUDGE_SQL` (#60) | **어느 DB 인가** (#454 — 문제 하나에 DB 하나). 스키마·시드·정답 쿼리. 상태를 묻는다면 확인 쿼리(#453) |
| `JUDGE_NOSQL` (#455) | 어느 제품인가. 시드·정답 명령·**끝난 뒤의 상태를 읽는 명령** |
| 언어 제한 (#419) | 특정 언어로만 푸는 문제인가. 아희·엄랭(#394)처럼 |
| 파일 여럿 (#457) | 파일 목록과 **고칠 수 없는 파일** |

## 2. 정해진 것으로 묶음을 만든다

형식은 **`docs/12_문제_묶음_형식.md`** 에 있다. 그것을 읽고 따른다 — 여기에 옮겨 적지
않는 이유는, 옮겨 적으면 형식이 바뀔 때 둘이 갈라지기 때문이다.

```
.problem-drafts/{slug}/
├── problem.json
└── testcases/1.in, 1.out, …
```

`problem.json` 의 예시는 **`scripts/seed-problems` 안의 파일들**이다. 열네 개가 이미 있고,
stdio·SQL·언어 제한이 모두 들어 있다.

### 지문에 반드시 들어가는 것

- 무엇을 구하는지 한 문장
- **제약 조건** (`1 ≤ N ≤ 100,000`)
- 입력 형식과 출력 형식
- 예제 입력·출력 **둘 이상**. 하나면 형식을 오해했는지 알 수 없다

### 테스트케이스

이 스킬이 만드는 것은 **손으로 셀 수 있는 것**까지다 — 예제와 경계 몇 개.

**정답을 채우는 일과 반례를 찾는 일은 다른 스킬이다** (#481·#482). 여기서 억지로 하면
`expectedOutput` 이 근거 없는 값이 되고, 그것이 가장 나쁜 결과다 — **틀린 기대 출력은
맞는 풀이를 떨어뜨린다.**

## 3. 끝내며 알린다

- 무엇을 정했고 **무엇을 사용자가 정해 줬는지**
- 아직 비어 있는 것 (정답 코드·대량 테스트케이스)과 다음에 쓸 스킬
- 올리는 방법: `POST /api/v1/admin/problems/imports` — **언제나 초안으로 들어간다**
